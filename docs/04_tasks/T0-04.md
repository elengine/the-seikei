# T0-04 保存の窓口の型と契約テスト

- 目的:保存の窓口(Repository)の型を確定し、どの実装でも守るべき振る舞いをテストとして先に書く。
- 関連要件:DR-01〜DR-05、02_architecture 5.2
- 前提:T0-03

## 作成するファイル

`src/core/storage/types.ts`、`tests/contract/repositoryContract.ts`、`tests/contract/stub.test.ts`

## 仕様:`src/core/storage/types.ts`

```ts
export type CollectionName =
  'settings' | 'terms' | 'zukan' | 'records' | 'sessions' | 'shop' | 'memories';

export interface Rec<T> {
  id: string;
  collection: CollectionName;
  data: T;
  createdAt: string;
  updatedAt: string;
  updatedBy: string;       // 端末ID
  deletedAt?: string;
  schemaVersion: number;
}

export interface BackupFile {
  app: 'seikei-game';
  exportedAt: string;
  schemaVersion: number;
  deviceId: string;
  recs: Rec<unknown>[];    // 論理削除されたものも含む
}

export interface ImportReport { added: number; updated: number; unchanged: number; rejected: number; }

export interface Repository {
  get<T>(collection: CollectionName, id: string): Promise<Rec<T> | undefined>; // 削除済みは undefined
  list<T>(collection: CollectionName): Promise<Rec<T>[]>;                       // 削除済みは含めない。id の昇順
  put<T>(collection: CollectionName, data: T, id?: string): Promise<Rec<T>>;   // id 省略時は uuid を振る
  remove(collection: CollectionName, id: string): Promise<void>;               // 論理削除。存在しなければ何もしない
  subscribe(collection: CollectionName, cb: () => void): () => void;           // 戻り値で購読解除
  exportAll(): Promise<BackupFile>;
  importAll(file: BackupFile): Promise<ImportReport>;                          // T0-07 で実装
}

// 移行・同期・バックアップ用の内部窓口(ゲーム側からは使わない)
export interface RawStore {
  readonly deviceId: string;                        // この端末のID
  getRaw(collection: CollectionName, id: string): Promise<Rec<unknown> | undefined>; // 削除済みも返す
  putRaw(rec: Rec<unknown>): Promise<void>;       // 日時や端末IDを書き換えずにそのまま保存
  allRaw(): Promise<Rec<unknown>[]>;
  getMeta(key: string): Promise<string | undefined>;
  setMeta(key: string, value: string): Promise<void>;
}

export const CURRENT_SCHEMA_VERSION = 1;
```

## 仕様:契約テスト `tests/contract/repositoryContract.ts`

実装を作る関数を受け取ってテスト群を登録する関数を export する。

```ts
export function runRepositoryContract(
  name: string,
  make: (clock: Clock, deviceId: string) => Promise<Repository & RawStore>
): void;
```

各テストは `createFixedClock('2026-01-01T00:00:00.000Z')` と端末ID `'dev-A'` で新しい実装を作る。確かめる振る舞い:

1. 存在しない id の `get` は undefined。
2. id を省略した `put` で、id が UUID v7、`createdAt === updatedAt`、`updatedBy === 'dev-A'`、`schemaVersion === CURRENT_SCHEMA_VERSION`。
3. 同じ id に2回 `put` すると、`createdAt` は1回目のまま、`updatedAt` が進み、data が新しい値になる。
4. `list` は削除済みを含まず、id の昇順。別のコレクションのものは含まない。
5. `remove` の後、`get` は undefined、`getRaw` は `deletedAt` 付きの Rec を返す。存在しない id の `remove` は例外を出さない。
6. `put` と `remove` の後に、そのコレクションの購読者が1回呼ばれる。購読解除後は呼ばれない。別コレクションの購読者は呼ばれない。
7. `exportAll` は削除済みを含む全 Rec と、`app`、`schemaVersion`、`deviceId` を返す。
8. `putRaw` で入れた Rec は、`getRaw` でそのまま(日時も含めて)取り出せる。
9. `setMeta` した値を `getMeta` で取り出せる。

## 仕様:`tests/contract/stub.test.ts`

`runRepositoryContract` を、まだ存在しない実装を import しようとせずに呼べることだけを確かめるため、**`describe.skip`** の中で「すべて未実装のメソッドを持つスタブ」を渡して登録する。T0-05 で本物の実装に対するテストファイルを別に作る。
