## 追加修正a:盤面の絵

### 1. ドラムの向きを90度回す(軸を縦にする)

- いまは、ドラムの軸が横向きで、両端の円盤が左右にあり、帯の区画が左から右へ並んでいる。これだと、左のクリールから来る糸が、ドラムの軸と同じ向きに進むことになり、実物と合わない。実物は、糸のシートがドラムの軸と直角に巻き付き、帯は**軸に沿って**隣へ並んでいく。
- 直し方:ドラムの**軸を縦**にする。
  - 両端の円盤は**上と下**(横長の楕円)。
  - 胴の木の桟は**縦長の板**を、左右に並べる(円筒の丸みに合わせて、中央を明るく、左右の端を暗く。`createLinearGradient` を横向きに)。
  - 帯の区画は、**上から下へ** sections 等分する。帯1本目が一番上。
  - 巻いた帯は、その区画を糸の色の**横の縞**で塗る(糸はドラムの周りを回るので、この向きで見ると横の線になる。柄の並びの色を、区画の高さの中で上から順に繰り返す)。
  - 結び目の束は、各帯の区画の**左の端**に描く。ピンの横木は、ドラムの左の縁に沿って縦に置き、帯ごとに1本のピンを、その区画の高さに描く。
- **台と筬が、今の帯の高さへ動く。** 実物では、帯を1本巻き終えると、台が隣の区画へ送られる。盤面でも、台と筬の縦の位置を、今の帯の区画の高さに合わせる。筬を通った糸は、今の帯の区画へまっすぐ(横向きに)入る。
  - 次の帯へ移るとき(帯の端を結ぶ演出の1秒)に、台が今の区画から次の区画へ、なめらかに動く(`tieProgress` を使う)。
- 切れ端の位置と当たり(`threadY`・`endPoint`)は、クリールと台のあいだの糸なので、台が動いても変えない。台が動く範囲と、切れ端の位置が重ならないように、台は切れ端より右に置く。

### 2. 帯の端を結んだときに、絵がはっきり変わる

- 管理者の指摘:「帯の端を結んでも絵があまり変わらない」。
- 直し方(上の1とあわせて):
  - 結ぶ演出の1秒のあいだに、今の帯の区画の左の端に、糸の色の輪が**大きく広がってから結び目の束に縮む**様子を描く(`tieProgress` 0→1)。
  - 結び終えた区画は、縞をいちばん濃く(`globalAlpha` 1)し、縁に濃い線を引いて「完了」が分かるようにする。
  - 台と筬が次の区画へ動く(上の1)。
  - 次の区画は、ピンに糸の束が掛かった状態になる。

### 3. 流れる印と、巻き始めの色(T2-08 の確認で見つけた点)

- 巻いているときの「流れる印」が、糸の線から外れて、縦一列に並んでいる。印は、糸の線の上(クリールから筬までの線、筬から今の帯までの線)に乗せて動かす。
- 巻き始めたばかり(1%)でも、区画全体が濃い色になる。巻いた量が少ないうちは薄く(`globalAlpha` を 0.15 から始めて、巻いた割合に応じて 1 まで上げる)する。

### テスト(renderer.test.ts・geometry.test.ts)

1. ドラムの端の円盤は、上と下にある(`ellipse` の中心の y が、ドラムの区画の上の端と下の端の近く)。
2. 帯の区画は上から並ぶ(`current` 0 の帯の区画の y が、`current` 1 より小さい)。
3. 台の縦の位置が、今の帯の区画の縦の中心に合う(`current` を変えると台の y が変わる。geometry.ts に `tableY(current, sections)` のような関数を置いて確かめてよい)。
4. `tieProgress` 0.5 のとき、結び目の輪が、0 と 1 のときより大きい。
5. 流れる印の点が、糸の線の上にある(印の y が、その糸の `threadY` か、筬から今の帯へ向かう線の上)。
6. 既存のテスト(切れ端の位置、文字、色の直書きなし、save/restore の順など)はそのまま通る。

## 追加修正b:操作欄

### 4. 操作欄があふれて、メッセージの1行目が見切れ、主ボタンが見えない

- 確認役の測定(960×720、帯を巻き終えた状態):操作欄の見えている高さ 609px に対して中身が 661px。横にもあふれてスクロールバーが出ている(ペダルの列が操作欄の幅より広い)。操作欄がスクロールすると、一番上のメッセージが上に隠れ、「帯の端を結ぶ」はスクロールしないと見えない。
- 直し方:
  - **メッセージは、操作欄の上に固定する。** 横長では、メッセージ欄を `position: sticky; top: 0`(背景は操作欄と同じ色)にして、操作欄がスクロールしても隠れないようにする。
  - **主ボタン(「巻き始める」「帯の端を結ぶ」)は、操作欄の下に固定する。** 横長では `position: sticky; bottom: 0`(クリール立ての道具の区画と同じ考え)。
  - **横にあふれない。** ペダルの列(溝+ボタン)は、操作欄の幅に合わせて縮む。溝の幅は最小 120px まで縮めてよい。ボタンは最小幅 96px(高さは 64px 以上のまま)。「踏み込む」が2行に折れないようにする(`white-space: nowrap`)。
  - 1180×820 では、今までどおりスクロールなしで収まること。
- テスト(tokens.test.ts など、base.css を読むテスト):`.game-frame__message` に、横長で `position: sticky` がある。主ボタンの区画に `position: sticky` がある。

### 5. 張りのメーターの幅が、状態の文字で変わる

- 管理者の指摘(スマホ縦):「『○ 適正』が『▲ 強すぎ』になると、文字数が変わってメーターの幅も変わる」。縦長ではメーターを横に並べている(T2-07 追加修正b)ので、右の状態の文字の幅が変わると、帯の幅が変わる。
- 直し方:状態の文字の欄の幅を、一番長い文字(「▲ 強すぎ」)に合わせて**固定**する(例:`width: 5.5em; flex: none;`)。横長も同じにする(横長では縦に並ぶので影響は小さいが、そろえておく)。
- テスト(pedalControl.test.ts):状態の文字の欄に、固定の幅のクラスが付く。(base.css を読むテスト):そのクラスに `width` と `flex: none` がある。
