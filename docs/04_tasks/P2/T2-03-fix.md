## 直す4点

1. **横に並べると、操作欄に収まらない。** いまは「戻す(120px)・溝(200px)・踏み込む(120px)」を横1列に並べていて、すき間を入れると 464px になる。1180×820 の操作欄は約 400px、412×915 は約 388px なので、はみ出す。
   - 直し方:溝の右に、ボタンを縦に並べる(上に「戻す」、下に「踏み込む」。横木を下げるほど速いので、下のボタンが速くする方)。溝の幅は 180px、横木の幅は 160px にする。合計の幅は 180 + 12 + 120 = 312px 以下になる。
2. **ボタンが、ほかのボタンと違う見た目になる。** 「踏み込む」「戻す」は `pedal__btn` のクラスだけで、共通のボタンのクラス(`btn`)が付いていない。T1-11 で `button` の既定の見た目を消したため、枠も背景も無い文字だけのボタンになる。
   - 直し方:`btn` と `btn--secondary` のクラスを付ける(`core/ui/widgets.ts` の `createButton` を使ってもよい)。
3. **決まりに無い色を使っている。** 溝とメーターの帯の背景が `var(--c-kinari-dark, #EDE7D5)` で、`--c-kinari-dark` は tokens に無いため、直書きの `#EDE7D5` が使われている。
   - 直し方:tokens にある色を使う(溝とメーターの帯の背景は `--c-white`)。直書きの色を消す。
4. **一番上と一番下で、横木が溝からはみ出す。** 横木の位置が `top: 値%` と `translate(-50%, -50%)` なので、0 では横木の上半分が溝の上に、100 では下半分が溝の下に出る。
   - 直し方:横木の上端の位置を「(溝の高さ − 横木の高さ)× 値 / 100」にする(`top: calc((100% - 64px) * 値 / 100)` とし、`translate` の縦方向はやめる)。押した位置から値を求める計算も、同じ範囲(横木の高さの半分を上下から除いた範囲)に合わせる。

## テスト(pedalControl.test.ts)

- 「踏み込む」「戻す」に `btn` のクラスがある。
- 溝の高さ 240px・横木の高さ 64px を仮定し、値 0 で横木の上端が 0px、値 100 で 176px(240 − 64)になる(style の値で確かめる)。
- 溝の上端から 32px の点を押すと 0、下端から 32px の点を押すと 100(横木の中心が指の位置に来る)。
- 既存のテスト1(上端 0、下端 100、真ん中 50)は、上の計算に合わせて期待値を変えてよい。理由は「確認役が横木の位置の計算を直したため」。
