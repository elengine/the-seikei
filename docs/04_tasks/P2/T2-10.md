## 1. 流れる印が、クリール側の切れ端の先で上へ飛ぶ(不具合。T2-10a)

- 原因:`geometry.ts` の `pointOnPath` の区間2(クリール側の切れ端 → 筬)で、行き先の y を `half`(−30〜+30)にしている。筬の高さ(`tableY − REED_RISE + half`)ではなく、**盤面の一番上(y≒0)**へ向かって印が動く。
- 直し方:
  - 糸の線の折れ点(頂点)を返す関数を `geometry.ts` に1つだけ置く(例:`threadPath(thread, threadCount, current, sections): {x, y}[]`)。**糸の線を描く処理(renderer)と、流れる印の位置(`pointOnPath`)の両方が、この頂点を使う。** 別々に計算しない(T2-07 追加修正2 の `threadY` と同じ考え)。
  - `pointOnPath` は、この頂点の折れ線の上を、長さの割合で進む点を返す。
- テスト(geometry.test.ts):
  - どの糸・どの `current` でも、`pointOnPath` の点は、`threadPath` の折れ線のどれかの線分の上にある(距離 0.5 以内)。
  - `along` を 0 から 1 まで増やしたとき、y は、糸の高さ(`threadY`)から筬の高さまでのあいだにあり、y < 50(盤面の上の端)にならない。

## 2. 糸が切れる位置(切れ端)が、糸の流れていない所に出る(不具合。T2-10a)

- 原因:切れ端の x が、クリール側 `CREEL_END_X = 380`、ドラム側 `DRUM_END_X = 460`。一方、糸の線は、クリール側の切れ端(380)の先で筬(`REED_X = 410`)へ向かって曲がる。ドラム側の切れ端(460)は筬より右にあり、そこには糸が通っていない(筬より右では、糸は帯の高さへ集まっている)。
- 直し方:
  - 糸の線を「コーン → まっすぐ横に進む区間 → 筬へ集まる区間 → 筬 → 今の帯」とする。**切れ端は2つとも、まっすぐ横に進む区間の上に置く**(y は `threadY`)。
  - 数値の目安(論理座標):まっすぐ横に進む区間はコーンから x 400 まで。クリール側の切れ端 x 290、ドラム側(筬側)の切れ端 x 360(2つの差は 60 以上。当たりの 64px 四方が重なりすぎないように)。筬は x 520 付近に置き、台は筬を中心に描く(台の左の端は、ドラム側の切れ端より右。切れ端の上に台を描かない)。
  - 切れた糸の絵(朱の線・垂れ)と、当たり(`endPoint`・`hitEnd`)は、この位置に合わせる。**`endPoint` は、`threadPath` の、まっすぐ横に進む区間の上の点を返す**ようにして、描く位置と当たりの位置が必ず同じになるようにする。
  - ほかの部品(クリール・筬・台・ドラム)が重ならないよう、`TABLE_AREA` などの区画の値も合わせて直してよい。
- テスト(geometry.test.ts・renderer.test.ts):
  - すべての糸で、`endPoint(t, 'creel')` と `endPoint(t, 'drum')` が、`threadPath` の線分の上にある。
  - `endPoint(t, 'drum').x − endPoint(t, 'creel').x ≥ 60`。どちらも、筬の x と台の左の端より左。
  - 'broken' のとき、切れた糸の朱の線の端の位置が、`endPoint` と同じ。
  - 既存の当たりのテスト(`hitEnd`)は、新しい位置で通る。

## 3. ドラムが回って見える(改善。T2-10b)

- 管理者の要望:「ドラムが回っているダイナミクスが、この作業の見どころのひとつ」。いまは、巻いているあいだもドラムの絵が止まったまま。
- 考え方:ドラムの回る角度 `drumAngle`(ラジアン)は、見た目だけの値なので、**logic の State には入れない**。controller が rAF の時間で進め、`drawBoard` の opts で renderer に渡す(`timeMs` や `tieProgress` と同じ扱い)。
  - 角度の進み方:`drumAngle += 速さ(speedOf) × DRUM_TURN_PER_SPEED × dtMs / 1000`。`DRUM_TURN_PER_SPEED` は `params.ts` に置く(初期値:ペダル 50 の速さで1秒に約 0.8 回転に見える値)。
  - 速さが 0 のとき(ペダル 0・糸切れ・帯の端を結ぶ前・裏に回ったとき)は、角度が進まない。
- 描き方(軸が縦の円筒として。すべて `drawDrum` の中):
  - **胴の木の桟**:桟は円筒の周りに等間隔に並んでいるものとし、桟 k の角度 `θ = drumAngle + 2π k / 桟の数`。正面から見た x は `中心 + 半径 × sin θ`、幅は `桟の幅 × cos θ`。`cos θ ≤ 0`(裏側)の桟は描かない。これで、桟が横に流れて、端で細くなって消える。
  - **巻いた帯**:縞(横の線)は回っても変わらないので、帯の面の上に、**糸の筋(細い縦の明るい線)を数本**、桟と同じ式で横に流す(`globalAlpha` 0.25 程度)。
  - **上と下の円盤**:円盤の中の放射状の線(スポーク)を、`drumAngle` だけ回して描く(楕円の上の点 `(cx + rx cos φ, cy + ry sin φ)`)。
  - 色は tokens だけを使う。
  - T2-08 追加修正2 の1(巻いている途中の帯の区画でも、桟を描いてから縞を重ねる)は、回る桟でも保つ。
- テスト(renderer.test.ts・controller.test.ts):
  - `drumAngle` だけを変えて2回描くと、桟の `fillRect` の x が変わる。同じ `drumAngle` なら同じ。
  - 裏側の桟(`cos θ ≤ 0`)は描かれない(桟の `fillRect` の数が、桟の数より少ない)。
  - controller:ペダルを踏んで巻いているあいだは、偽の rAF で進めると renderer に渡す `drumAngle` が増える。糸が切れたあと・ペダル 0 のあいだは増えない。
