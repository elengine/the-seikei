## 仕様:移行

```ts
export interface Migration {
  from: number;            // この版の Rec を
  to: number;              // この版にする(from + 1 であること)
  migrate(rec: Rec<unknown>): Rec<unknown>;
}
export const MIGRATIONS: Migration[] = [];   // P0 では空

// store 内の全 Rec を現在の版(targetVersion)まで順に移行して保存する。
// meta 'schemaVersion' を読み、なければ targetVersion を書いて終わる(初回起動)。
// 途中の Migration が見つからなければ例外。移行中の例外は、そのまま呼び出し側に投げる。
export async function runMigrations(
  store: RawStore, migrations: Migration[], targetVersion: number
): Promise<{ from: number; to: number; migrated: number }>;

// Rec の配列を移行する(バックアップ読み込み用)。純粋関数。
export function migrateRecs(recs: Rec<unknown>[], migrations: Migration[], targetVersion: number): Rec<unknown>[];
```

- 移行は、全 Rec を移行し終えてから保存する。途中で例外が出た場合、保存済みのデータを変えない。
- 移行が終わったら meta 'schemaVersion' を更新する。

## 仕様:importAll

1. `file.app !== 'seikei-game'` なら、全件 rejected として何もせず返す。
2. `file.schemaVersion > CURRENT_SCHEMA_VERSION` なら、全件 rejected(新しすぎるバックアップ)。
3. 古ければ `migrateRecs` で現在の版にする。
4. 各 Rec について、`getRaw` で手元の Rec を探す。
   - なければ `putRaw` して added。
   - あれば `mergeRec` の結果を求め、手元と同じなら unchanged、違えば `putRaw` して updated。
5. 変更のあったコレクションの購読者に通知する。

## テスト(先に書く)

移行:
1. meta がない store では、何も移行せず schemaVersion を書く。
2. テスト用の Migration(版1→2 で data に `x: 1` を足す)を渡すと、全 Rec が版2になり data に x が入る。
3. 版1→3 を求めたのに 2→3 の Migration がなければ例外で、データは変わらない。

importAll(fake-indexeddb を使う):
4. 空の repository に読み込むと、全件 added。
5. 同じファイルを2回読み込むと、2回目は全件 unchanged。
6. 手元の settings の名前が新しく、ファイルの屋号が新しい場合、両方が残る(fieldNewer)。
7. app が違うファイル、版が新しすぎるファイルは全件 rejected。
