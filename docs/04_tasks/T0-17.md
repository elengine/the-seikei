# T0-17 起動処理と PWA

- 目的:起動時のデータ移行と永続化の要求を行い、ホーム画面に追加できる PWA として配信する。
- 関連要件:NFR-A-01、NFR-A-02、NFR-X-02、02_architecture 8章、03_basic_design 8章
- 前提:T0-07、T0-16

## 作成・変更するファイル

`src/app/boot.ts`(新規)、`src/main.ts`(変更)、`vite.config.ts`(変更)

## 仕様:boot.ts

```ts
export type BootResult = { ok: true; ctx: AppContext } | { ok: false; reason: string };
export async function boot(opts: { dbName: string; clock: Clock; navigate: (p: string) => void }): Promise<BootResult>;
```

1. `createAppContext` を作る。
2. `runMigrations(ctx.repo, MIGRATIONS, CURRENT_SCHEMA_VERSION)` を実行する。例外なら `{ ok: false, reason }` を返し、ログに error を残す。
3. `navigator.storage?.persist?.()` を呼ぶ(結果は info ログに残すだけ。失敗しても続行)。
4. `{ ok: true, ctx }` を返す。

## 仕様:main.ts

- `boot` が失敗したら、画面に「データの準備でうまくいきませんでした。管理者に連絡してください。」と大きく表示し、それ以外は何もしない(データを書き換えない)。
- 成功したら、これまでのルート(`/`、`/settings`、`/settings/terms`、`/admin`)で ScreenManager を開始する。

## 仕様:vite.config.ts(vite-plugin-pwa)

- `registerType: 'prompt'` とし、更新を促す表示は出さない。新しい Service Worker は、アプリがすべて閉じられた後の次回起動時に切り替わる(`skipWaiting` と `clientsClaim` を有効にしない)。
- `workbox.globPatterns` に js、css、html、png、json を含め、全ファイルを事前にキャッシュする。
- manifest:
  - `name`: `整経ゲーム`、`short_name`: `整経`
  - `start_url`: `./`、`scope`: `./`、`display`: `standalone`、`orientation`: `any`
  - `background_color`: `#F7F3E8`、`theme_color`: `#4F5B47`、`lang`: `ja`
  - icons:`icons/icon-192.png`(192)、`icons/icon-512.png`(512)、`icons/icon-maskable-512.png`(512、purpose `maskable`)
- `define` で `__APP_VERSION__` に package.json の version を埋め込み、管理者メニューのデータの状態に表示する(adminScreen.ts への1行の追加は可)。

## 完了条件

- `npm run check`、`npm test`、`npm run build` が成功し、`dist` に manifest と Service Worker が出力される。
- デプロイ後、管理者が実機で次を確かめる(実装担当は手順を報告に書く):
  1. iPad Air の Safari で開き、共有ボタン →「ホーム画面に追加」。アイコンから起動するとアドレスバーのない全画面で開く。
  2. Android(POCO X7 Pro、Galaxy Z Fold 8)の Chrome で「ホーム画面に追加」または「アプリをインストール」。
  3. 一度起動した後、機内モードにしても起動できる。
  4. 設定を変えてアプリを完全に終了し、再起動しても残っている。
  5. 管理者メニューで永続化の状態を確認する。
