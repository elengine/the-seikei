# T0-06 競合解決ルール(merge)

- 目的:同じ Rec が2つの端末で別々に更新されたとき、どちらを残すかを決める純粋関数を作る。P0 ではバックアップの読み込みで使い、P6 では同期で使う。
- 関連要件:DR-06、02_architecture 5.2・6章
- 前提:T0-04

## 作成するファイル

`src/core/storage/merge.ts`、`src/core/storage/merge.test.ts`

## 仕様

```ts
export type MergeRule = 'newer' | 'union' | 'max' | 'fieldNewer';

export const RULES: Record<CollectionName, MergeRule> = {
  settings: 'fieldNewer',
  terms: 'newer',
  zukan: 'union',
  records: 'max',
  sessions: 'newer',
  shop: 'newer',
  memories: 'newer',
};

// a と b は同じ collection・同じ id であること(違えば例外)。
// 戻り値は残すべき Rec。どちらかと完全に同じなら、その Rec をそのまま返してよい。
export function mergeRec(a: Rec<unknown>, b: Rec<unknown>): Rec<unknown>;

// 「新しい方」の判定。updatedAt が大きい方。同じなら updatedBy の文字列が大きい方。
export function isNewer(a: Rec<unknown>, b: Rec<unknown>): boolean;
```

### ルールの中身

- **newer**:`isNewer` で新しい方を丸ごと採る。削除(deletedAt)も新しい方に従う。
- **union**(図鑑):data は `{ obtainedAt: string; source: string; count: number }`。
  - obtainedAt は早い方、source は obtainedAt が早い方のもの、count は大きい方。
  - 削除は無視する(どちらかが入手済みなら入手済み)。結果の deletedAt は付けない。
  - updatedAt・updatedBy は新しい方のものを使う。
- **max**(成績):data は `{ bestStars: number; plays: number; best: Record<string, number> }`。
  - bestStars、plays は大きい方。best はキーごとに大きい方(片方にしかないキーはそのまま残す)。
  - 削除は newer と同じ扱い。updatedAt・updatedBy は新しい方。
- **fieldNewer**(設定):data は任意のキーと、`_updated: Record<string, string>`(キーごとの更新日時)を持つ。
  - `_updated` 以外のキーごとに、`_updated[キー]` が新しい方の値を採る。片方にしか `_updated[キー]` がない場合はそちらを採る。どちらにもない場合は、Rec 全体で新しい方の値を採る。
  - 結果の `_updated` はキーごとに新しい方の日時。
  - 削除は newer と同じ扱い。updatedAt・updatedBy は新しい方。

## テスト(先に書く)

各ルールについて最低次のケースを書く。
1. newer:新しい方が採られる。updatedAt が同じときは updatedBy の大きい方。新しい方が削除済みなら削除済みになる。
2. union:早い obtainedAt と、その source が残り、count は大きい方。片方が削除済みでも入手済みのまま。
3. max:bestStars・plays・best の各キーで大きい方。片方にしかない best のキーが残る。
4. fieldNewer:A 端末で名前、B 端末で屋号を変えた2つを統合すると、両方の変更が残る。
5. collection か id が違う Rec を渡すと例外。
6. `mergeRec(a, b)` と `mergeRec(b, a)` の結果が(data・deletedAt・updatedAt について)同じになる。全ルールで確かめる。
