# 実装担当への共通ルール(全タスク共通)

あなたは「整経ゲーム」の実装担当です。タスク仕様書(T0-xx.md など)1つにつき、1つの作業を行います。
作業の前に必ずこのファイルと、指定されたタスク仕様書を読んでください。

## 作業の手順

1. リポジトリ直下の `PROGRESS.json` を読み(T0-00 を除く)、前提タスクが `done` に入っていることを確認する。入っていなければ作業せず、その旨を報告する。
2. `PROGRESS.json` の `current_task` を今回のタスクIDにする。
3. タスク仕様書の「テスト」に書かれたテストを先に書き、失敗することを確認する(テストがないタスクは除く)。
4. 実装してテストを通す。
5. `npm run check` と `npm test` を実行し、両方とも成功させる。
6. `PROGRESS.json` を更新する(`done` にタスクID、`checks` は今回のタスク分だけに置き換え、詳しい記録は `docs/progress_log.md` の末尾に追記)。
7. `git commit` する。メッセージは `T0-xx: タスク名` とする。
8. 最後に、変更したファイルの一覧、テストの結果、気づいた点を報告する。

## 守ること

- **「変更するファイル」に書かれたファイル以外は変更・作成しない。** 必要だと思ったら、作業を止めて理由を報告する。
- 下の「使ってよいライブラリ」以外を追加しない。
- 型は仕様書に書かれたとおりに作る。名前や引数を変えない。
- `any` を使わない(どうしても必要なら `unknown` を使って型を絞る)。
- 1ファイルは 300 行以内に収める。超えそうなら報告する。
- 画面に出す整経用語やゲーム名を直接書かない。`terms.t('キー')` を使う(T0-11 以降)。
- 時刻・乱数・ID は `src/core/clock` を使う。`Date.now()`、`Math.random()`、`crypto.randomUUID()` を直接呼ばない(clock の中を除く)。
- 色・文字サイズ・間隔の数値を直接書かない。`src/core/ui/tokens.ts` と CSS 変数を使う(T0-08 以降)。
- 依存の向きは `app → games / zukan → core → content` の一方向のみ。`src/core` から `src/app`、`src/games`、`src/zukan` を import してはならない(リンターが検出する)。
- **画面の文言は、大人が読む前提で書く(2026-09-30 管理者の指示。今後のゲームも同じ)。** 遊ぶのは大人(引退した整経の職人)。子ども向けのひらがな書きにしない。常用漢字で書く言葉は漢字で書く(例:「もどる」ではなく「戻る」、「たしかめる」ではなく「確認する」、「えらぶ」ではなく「選ぶ」)。ただし、難しすぎる漢字や業界外の硬い言い回しは避け、平易な言葉にする。ほめ言葉も、子ども向けの言い方(「よくできました」など)にしない。
- テストが通らないまま完了扱いにしない。テストを消したり、期待値を実装に合わせて書き換えたりしない。

## 使ってよいライブラリ

| 種類 | パッケージ |
|---|---|
| 実行時 | `dexie`, `gsap` |
| 開発用 | `vite`, `typescript`, `vitest`, `jsdom`, `fake-indexeddb`, `eslint`, `@eslint/js`, `typescript-eslint`, `globals`, `vite-plugin-pwa` |

TypeScript は 5.x に固定する(typescript-eslint が 7 に未対応のため)。上げる場合は管理者の承認を得る。

## 不具合修正のとき

管理者から不具合の指摘を受けて直すときは、まず不具合を再現するテストを `tests/regression/` に書き、失敗することを確認してから直す。テスト名は `bugNN_内容`(NN は `PROGRESS.json` の `open_bugs` の番号)とする。

## 公開について

このリポジトリと公開サイトは誰でも見られる。コード、内容データ、コミットメッセージ、PROGRESS.json に、家族を特定できる情報(詳しい地名、年齢、実名、屋号など)を書かない。品番や機屋の名前は架空のものを使う。

## 困ったとき

仕様があいまい、または仕様どおりでは実現できない場合は、推測で進めずに作業を止め、どこがどう問題かを報告する。

## 名前について

- リポジトリ名と公開URLのサブパスは `the-seikei`(`https://elengine.github.io/the-seikei/`)。
- 端末内のデータベース名(`seikei-game`)とバックアップファイルのアプリ識別子(`app: 'seikei-game'`)は、アプリ内部の名前なので**リポジトリ名に合わせて変えない**。
- マニフェストの id は `'the-seikei'` で確定。父の端末に入れた後に変えると別アプリ扱いになるため、今後は変更しない。
