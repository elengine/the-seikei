## 不具合

`controller.ts` は、始める状態を `props.resume` から読む(`opts.resume` は読まない)。`index.ts` は、一覧からお題を選んだときに、`mount` で受け取った `props` をそのまま広げて(`...wrappedProps`)渡しているため、`props.resume` が「mount のときの値」のまま残る。その結果:

1. **「途中」のお題を押しても、再開しない。** 最初から開いた(`props.resume` が無い)あとで、プレイ → 「一覧に戻る」→「途中」のお題を押すと、新しい状態で始まる。
   - 確認役の再現:s1 で「外す」を選んでから一覧に戻り、s1 を押すと、道具が「外す」ではなく最初の箱に戻っていた。
   - T1-15 のテスト2は、s1 の最初の状態で選ばれている箱(`kon-a`)をもう一度選んでから確かめているため、再開しなくても通ってしまう。ブラウザ確認の「選んでいた箱のまま再開」も同じ理由で、区別がつかない。
2. **「続きから」で開いたあとに、一覧から別のお題を始めると、前のお題の盤面が出る。** `props.resume`(前のお題の状態)が残っているため、選んだお題ではなく前のお題が始まる。
   - 確認役の再現:s1-2 の状態で `resume` して開き、「一覧に戻る」→ s1 を押して「始める」→ 始まったのは s1-2 だった。

## 直し方(`index.ts`)

- プレイ画面を開く処理を1つの関数にまとめる(いまは「一覧から選んだとき」と「resume で開いたとき」に同じ `controllerProps` の組み立てが2か所ある)。
  - `startPlay(puzzleId: string, resume: CreelState | undefined)`:`controllerProps` の `resume` に、**引数の resume を明示して入れる**(`...wrappedProps` のあとに `resume` を上書きする)。
- 一覧から選んだとき:選んだお題が途中のお題なら、途中の状態を `resume` に渡す。それ以外は `undefined`(新しく始める)。
- `mount` のときの `props.resume` は、最初の1回だけ使う。
- 途中のお題の id を取り出す処理も、1つの関数にまとめる(いまは2か所で同じ式を書いている)。
