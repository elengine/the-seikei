# T1-22 iPhone・iPad(Safari):ホームのカードに無駄な余白ができる(原因を WebKit で確かめてから直す)

- 目的:管理者の実機確認(2026-10-06、iPhone のホーム画面から起動、縦・横、スクリーンショット付き、会話)「スタート画面のカードの余白が無駄に多い。縦も横も。Android では起きない」。
- 管理者の条件:**原因は推測で決めず、技術的な裏付けを取る**。iPhone 固有か、iPad でも起きるかを特定する。同じ原因の書き方をしているほかの画面も**すべて**直す。**Android(Chrome)に影響を出さない。**
- 前提:T1-21。
- 進め方:**調べる → 直す の2つのコミット**(T1-22a:調べた結果を `docs/progress_log.md` に書くだけ。T1-22b:直す)。最後に version を patch で上げる。

## 見えていること(スクリーンショット)

- ホームのゲームのカードが縦に長く伸び、説明の文と、下の端の「お題 15」のあいだに大きな空白がある(縦の1列でも、横の3列でも)。
- カードの小さな絵・題名・説明の大きさは正しく見える。

## T1-22a:WebKit で再現して、原因を数字で確かめる

- iPhone・iPad の Safari と同じ描画の仕組み(WebKit)を、**Playwright の WebKit** で動かして確かめる(作業の道具としてだけ使う。`package.json` には足さない。`npx playwright install webkit` などで作業環境にだけ入れる。入れられないときは作業を止めて報告)。
- 本番と同じビルド(`npm run build` → `vite preview`)を、Chromium と WebKit の両方で、412×915・915×412・1180×820(iPad 横)・820×1180(iPad 縦)で開き、次を測って表にする:
  - 各カード(`.game-card`)の高さ、その中の各要素(`.game-card__art` の SVG、題名、説明、状態)の高さと位置、カードの中身の合計とカードの高さの差。
  - `.home__games`(グリッド)の各行の高さ。
- 差が出た所について、**原因の要素と CSS の指定を特定する**(その指定を一時的に変えると WebKit の差が消える、ことで裏付ける)。確認役の見当:カードの絵の SVG(`width: 100%; height: auto;`、`viewBox` だけで `width`・`height` の属性が無い)を、WebKit がグリッドの行の高さを決めるときに実際より大きく見積もっている(SVG の既定の大きさ 300×150 から計算する、など)。**見当が外れていてもよい。数字で分かったことを書く。**
- 同じ原因になる書き方を、**アプリ全体で探す**(`grep` で、`viewBox` だけの SVG を `width: 100%`・`height: auto` で並べている所、`<button>` を `display: flex/grid` にしてグリッドに並べている所、など、特定した原因の形)。見つかった画面(遊び方の絵・一覧の色見本・結果の画面など)も、WebKit で同じく測る。
- iPad について:WebKit は iPhone と iPad で同じなので、iPad の大きさで WebKit が同じ差を出せば「iPad でも起きる」と結論する。

## T1-22b:直す

- 特定した原因に合わせて直す(例:SVG に `aspect-ratio` を付ける、`width`・`height` の属性を付ける、`display: block` にする、グリッドの行を `align-items: start` にする、など。**直し方も数字で確かめる**)。
- **Android(Chromium)に影響を出さない**:直す前と後で、Chromium の5つの大きさ(412×915・915×412・880×700・700×880・1180×820)のホームと、見つかったほかの画面の、各要素の大きさと位置が**1px も変わらない**ことを測って表にする。変わる場合は直し方を変える。
- 直したあと、WebKit で、カードの高さ = 中身の高さ + 余白(padding)になったこと(差が数 px 以内)を測る。
- テスト:jsdom では描画を確かめられないので、CSS の指定(例:SVG に `aspect-ratio` がある)をテストで確かめる。
