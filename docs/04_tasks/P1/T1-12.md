## A(T1-12a):結果の表示とチュートリアルの文字が 16px になっている

- 確認役の測定:結果の表示の文字(「完璧です!」、★★★、「たしかめた回数 1回」、「あたらしく集めた柄」、柄の名前)は、すべて 16px だった。チュートリアルの文(`tutorial__text`)とページ数(`tutorial__counter`)も 16px だった。ボタンだけは 22px。
- 原因:`result__praise`・`result-stars`・`result__lines`・`result-patterns`・`tutorial__text`・`tutorial__counter` の CSS が `base.css` に無く、ブラウザの既定の 16px になっている。`body` にも文字の大きさの指定が無い。T0-13 の仕様(チュートリアルの文は `--fs-body`)も満たしていない。
- 直し方(`base.css`):
  1. `body` に `font-size: var(--fs-body);` を指定する。指定を忘れた文字も 20px 以上になるようにするため。
  2. 結果の表示:
     - `.result__praise`:`--fs-heading`、太字、中央揃え、`margin: 0`。
     - `.result-stars`:`calc(var(--fs-number) * 1.5)`、中央揃え、色 `--c-wood`、`margin: 0`、`letter-spacing: 0.1em`。
     - `.result__lines`:`--fs-body`、行の高さ 1.5、`list-style: none`、`margin: 0`、`padding: 0`。
     - `.result-patterns`:`--fs-body`。`resultView.ts` で、中の2つの `p` に `result-patterns__label`(太字)と `result-patterns__names` のクラスを付け、どちらも `margin: 0`。
  3. チュートリアル:`.tutorial__text` と `.tutorial__counter` を `--fs-body` にする。
- テスト:
  - `tokens.test.ts`(`base.css` を読むテスト):`body` の宣言に `font-size: var(--fs-body)` がある。`.result__praise`・`.result-stars`・`.result__lines`・`.result-patterns`・`.tutorial__text`・`.tutorial__counter` の宣言があり、それぞれ `font-size` に `var(--fs-` を含む。
  - `gameParts.test.ts`:柄の欄の2つの `p` に、`result-patterns__label` と `result-patterns__names` のクラスが付く。
- ブラウザ確認:下の「文字の大きさを調べる JavaScript」を、ホーム・設定・お題一覧・プレイ画面・チュートリアル・結果の表示で実行し、どれも「20px 未満の文字なし」になることを報告する。

```js
// 画面に見えている文字のうち、20px 未満のものを一覧にする
[...document.querySelectorAll('body *')]
  .filter((e) => [...e.childNodes].some((n) => n.nodeType === 3 && n.textContent.trim()))
  .filter((e) => e.getBoundingClientRect().width > 0 && parseFloat(getComputedStyle(e).fontSize) < 20)
  .map((e) => `${e.tagName}.${e.className} ${getComputedStyle(e).fontSize} ${e.textContent.trim().slice(0, 12)}`);
```

## B(T1-12b):縦長で、画面が横に 24px はみ出す

- 確認役の測定(412×915、段階1):盤面の列(`game-frame__stage-col`)と操作欄(`game-frame__panel`)の幅が 412px で、左端が 12px、右端が 424px。画面の幅 412px を 12px 越え、右の余白も入れて 24px ぶん横にスクロールする。
- 原因:`gameFrame.ts` の `applyLayout` が、縦長で盤面の列と操作欄の幅を `innerW`(parent の幅)にしている。`.game-frame__body` の左右の余白(padding 12px×2)を引いていない。横長でも、「盤面の列(65%)+ 操作欄(残り)」が `innerW` になっていて、余白と間の隙間(12px)を引いていない。いまは flex で縮んで見えないだけ。
- 直し方(`gameFrame.ts`):
  - 幅の計算を、純粋な関数にして export する。

```ts
/** body の中の幅を、盤面の列と操作欄に分ける。bodyInnerW は body の左右の余白を引いた幅、gap は列のあいだの隙間 */
export function splitWidths(layout: 'landscape' | 'portrait', bodyInnerW: number, gap: number): { stageColW: number; panelW: number };
// landscape: stageColW = Math.floor((bodyInnerW - gap) * 0.65)、panelW = bodyInnerW - gap - stageColW
// portrait : stageColW = bodyInnerW、panelW = bodyInnerW
```

  - `applyLayout` の `bodyInnerW` は、`body.clientWidth` から左右の padding を引いた値。`clientWidth` が 0 のとき(テストの環境など)は `innerW` を使う。`gap` は `getComputedStyle(body).columnGap`(測れないときは 0)。
- テスト(`gameParts.test.ts`):
  - `splitWidths('portrait', 388, 12)` → `{ stageColW: 388, panelW: 388 }`。
  - `splitWidths('landscape', 1156, 12)` → `stageColW + panelW + 12 === 1156`、`stageColW === Math.floor(1144 * 0.65)`。
- ブラウザ確認(本番と同じビルド、ポートは固定):次の大きさで段階1と段階5を開く。`document.documentElement.scrollWidth`、`.game-screen` の `scrollWidth` と `clientWidth` を報告する。どれも、`scrollWidth` が `clientWidth` を越えないこと。
  - 412×915、360×800(細いスマホ)、1180×820、960×720、820×1180(iPad 縦)
  - 1180×820 の段階5で、操作欄のスクロールがないこと(今までどおり)。
