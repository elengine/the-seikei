## T1-11a:文字と見た目

1. **画面の文字の書体が決まっていない。** いまは `html`・`body` に `font-family` が無く、ボタンなどは `inherit` で親から受け継ぐだけ。Android の Chrome では既定がゴシック体なので気づかないが、**iPad の Safari では、書体を指定しないと日本語が明朝体で表示される。** Canvas は `FONT_FAMILY`(`"Hiragino Sans", "Noto Sans JP", sans-serif`)で描いているので、盤面と操作欄で書体が食い違う。
   - `:root` に `--font-family` を足し、値は `tokens.ts` の `FONT_FAMILY` と同じにする。`html, body` に `font-family: var(--font-family)` を指定する。
   - テスト(`tokens.test.ts`):`base.css` の `:root` の `--font-family` が `FONT_FAMILY` と同じ。`html, body` の宣言に `font-family: var(--font-family)` がある。
2. **iPad・iPhone の Safari は、横向きにすると文字を自動で大きくすることがある。** `html, body` に `-webkit-text-size-adjust: 100%; text-size-adjust: 100%;` を足す。
3. **行の高さが書体で変わる。** `line-height` を指定していない所は、書体ごとの既定の値になる。ヒラギノとNotoでは高さが違うので、iPad では操作欄の高さが変わる。`html, body` に `line-height: 1.4` を指定する。
4. **Safari のボタンの既定の見た目。** `button` に `-webkit-appearance: none; appearance: none;` を指定する。あわせて、タップしたときの灰色の四角を消すため、`html, body` に `-webkit-tap-highlight-color: transparent;` を足す。
- テスト(`tokens.test.ts`):2〜4 の宣言が `base.css` にあること(文字列で確かめてよい)。
- 3 で行の高さが変わるので、**ブラウザ確認で 1180×820 の段階5の操作欄の `scrollHeight`・`clientHeight` を測り直す。** スクロールが出る場合は、区画のあいだの間隔(8px 未満にはしない)や見出しの下の余白で詰める。文字を 20px 未満にしたり、ボタンを 64px 未満にしたりして詰めてはいけない。詰めきれないときは、そこで止まって報告する。

## T1-11b:音と保存

1. **音が途中から鳴らなくなる。** いまは、最初の `pointerdown` で1回だけ `audio.unlock()` を呼ぶ(`main.ts`、`{ once: true }`)。
   - iPad の Safari は、アプリが裏に回ったり、電話や通知が来たりすると、音の出力(AudioContext)を止める(状態が `suspended` や `interrupted` になる)。止まったあとは、もう一度、利用者の操作の中で `resume()` を呼ばないと鳴らない。
   - Safari は、`pointerdown` を音を鳴らしてよい操作と認めないことがある。`pointerup`・`touchend`・`click` で呼ぶのが確実。
   - 直し方:
     - `audio.ts` の `unlock()` は、何度呼ばれてもよい形にする(すでにある)。`ctx.state !== 'running'` のときだけ `resume()` を呼ぶ。
     - `play()` の最初で、`ctx.state !== 'running'` なら `resume()` を呼ぶ(失敗は無視する)。
     - `main.ts` は、`pointerup`・`touchend`・`click` のたびに `ctx.audio.unlock()` を呼ぶ(`once` を外す。`{ passive: true }`)。
   - テスト(`audio.test.ts`):偽の AudioContext の `state` を `'suspended'`・`'interrupted'` にすると、`unlock()` と `play()` で `resume` が呼ばれる。`'running'` のときは呼ばれない。
2. **アプリを閉じたときの途中保存。** いまは `visibilitychange` の `hidden` だけで途中保存している。iPad でアプリの切り替え画面からアプリを閉じたときは、`visibilitychange` の後にすぐ止められることがあるので、`pagehide` でも同じ保存を行う(同じ関数を呼ぶ)。片付けのときに `pagehide` も解除する。
   - テスト(`gameScreen.test.ts`):`pagehide` を送ると、途中保存(`sessions` への put)が1回行われる。unmount の後は行われない。

## T1-11c:回転と、バックアップの書き出し

1. **回転したときの配置の遅れ。** Safari では、回転の直後の `resize` のときに、まだ新しい大きさになっていないことがある。いまの `gameFrame` は、`resize`・`orientationchange`・`visualViewport` の `resize` の次のフレームで1回だけ配置し直すので、古い大きさのまま配置されるおそれがある。
   - 直し方:`gameFrame.ts` で、`parent` の大きさも ResizeObserver で見張り、変わったら配置し直す(footer を見張っているものと同じ ResizeObserver に `observe(parent)` を足してよい)。`destroy` で解除する(すでに `disconnect` している)。
   - テスト(`gameParts.test.ts`):ResizeObserver を偽物にし、`parent` が observe されていること。偽の ResizeObserver の通知を送ると `onStageResize` が呼ばれること。
2. **バックアップの書き出しが iPad で失敗するおそれ。** いまは、ボタンを押したあとに `await ctx.repo.exportAll()` を待ってから `navigator.share()` を呼んでいる。Safari は、利用者の操作から時間が空いたり、間に待ち時間が入ったりすると、`share()` を `NotAllowedError` で断ることがある。いまは、そのときに記録を残すだけで、何も保存されない。
   - 直し方:`share()` が `NotAllowedError` で失敗したら、今の「`a` 要素の `download` で保存する」方法に切り替える。利用者が共有の画面を閉じた(`AbortError`)ときは、何もしない。
   - テストは不要(ブラウザ確認もしなくてよい)。確認役がコードを読んで確かめる。
