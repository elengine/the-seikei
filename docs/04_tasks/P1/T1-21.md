## T1-21a-1:縦で起動すると、上の縞(藍の点線)がにじむ

- 見えていること:時計・電池の表示のすぐ下に、上の縞が、ぼかしがかかったように見える(iPhone の縦)。横や Android では起きない。
- 原因の見当(確認役):新しい iOS は、ホーム画面から起動したアプリでも、画面の上の端の近く(時計の表示の帯とその少し下)に重なる中身を**ぼかして見せる**。上の縞は `#app` の `padding-top: env(safe-area-inset-top)` のすぐ下にあり、このぼかしの帯に入っている。
- 直し方(どちらか、または両方。結果を報告に書く):
  1. `index.html` に `<meta name="apple-mobile-web-app-status-bar-style" content="default">`(と `apple-mobile-web-app-capable`)を足し、時計の表示の帯を不透明にして、中身がその下から始まるようにする。
  2. 上の端の帯(`env(safe-area-inset-top)` の高さ)を、ページの地の色の**無地**で埋め(`#app::before` など、`position: fixed`)、縞はその下に置く。縞と時計の帯のあいだに 4px ほどの余白。
- Android・PC の見た目は変えない。

## T1-21a-2:縦 → 横 → 縦に回すと、画面全体が上にずれる

- 見えていること:縦で起動 → 横に回す → 縦に戻すと、画面全体が上へずれ、上の部分が時計の表示の下に入る(スクリーンショット)。
- 原因の見当:ホーム画面から起動した Safari でよく知られた動き。回転のあと、文書がわずかにスクロールした位置のまま残る、または高さ(`100%`・`100vh`)の計算が回転前のまま残る。
- 直し方:
  - `html`・`body` は `height: 100%; overflow: hidden;`、`#app` は `position: fixed; inset: 0;`(中の画面ごとに必要な所だけスクロールする今の形は変えない)。高さは `100dvh` を使える所は使う。
  - 回転・大きさの変化のとき(`viewport.ts` の通知。`orientationchange`・`resize`・`visualViewport` の `resize`)に、`window.scrollTo(0, 0)` をして文書のずれを戻す(画面の中のスクロールできる欄は戻さない)。回転の直後は大きさの反映が遅れることがあるので、通知のあと 1 フレームと 300ms 後にもう一度戻す。
- テスト:大きさの変化の通知が来ると `window.scrollTo(0, 0)` が呼ばれる(300ms 後にも)。

## T1-21b:ホームの版の表示が途中で折り返す

- 見えていること:「バージョン 0.3.15 (2026-10-」で折り返し、「05)」が次の行に出る(iPhone の縦)。
- 原因:題名の列が右上の設定のボタンの分だけ狭く、版の行もその幅に収めている。
- 直し方:**版の行は、画面の幅いっぱい**を使う(設定のボタンの下まで伸ばしてよい。題名の列からは出して、見出しの下に置く)。それでも入らない狭い画面では、**「(」の前でだけ**折り返す(版の番号と日付はそれぞれ途中で折り返さない:`white-space: nowrap` の2つの部分に分ける)。
- テスト:版の行が、版の番号の部分と日付の部分の2つの要素で、それぞれ折り返さない指定。
