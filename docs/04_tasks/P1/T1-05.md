- 前提:P0 完了

## 仕様:図鑑

```ts
export interface ZukanData { obtainedAt: string; source: string; count: number; }
export interface ZukanRegistry {
  unlock(patternId: string, source: GameId): Promise<{ isNew: boolean }>;
  has(patternId: string): boolean;          // 同期(キャッシュ)
  all(): Map<string, ZukanData>;            // 同期(キャッシュ)
  onChange(cb: () => void): () => void;
}
export async function createZukanRegistry(repo: Repository, clock: Clock): Promise<ZukanRegistry>;
```

- zukan コレクション、id = patternId。
- 未入手なら `{ obtainedAt: now, source, count: 1 }` で登録して isNew = true。入手済みなら count を 1 増やすだけで isNew = false。
- キャッシュを持つため、共通の決まりどおり `repo.subscribe('zukan', …)` で外からの変更を読み直す。

## 仕様:成績

```ts
export interface RecordData { bestStars: number; plays: number; best: Record<string, number>; }
export interface Records {
  get(gameId: GameId): RecordData;                         // 無ければ { 0, 0, {} }。同期(キャッシュ)
  add(gameId: GameId, stars: number, best: Record<string, number>): Promise<void>;
  onChange(cb: () => void): () => void;
}
export async function createRecords(repo: Repository): Promise<Records>;
```

- records コレクション、id = gameId。
- `add` は plays を 1 増やし、bestStars は大きい方、best はキーごとに大きい方を残す。
- `repo.subscribe('records', …)` で外からの変更を読み直す。

## テスト(fake-indexeddb)

図鑑:
1. 初めての unlock で isNew = true、2回目で false・count 2。
2. 作り直しても has が true(保存されている)。
3. repo に直接 put した図鑑の記録が、has と onChange に反映される。

成績:
4. add を2回(星2・星3、best `{ 'puzzle:s1': 2 }` と `{ 'puzzle:s1': 3, 'puzzle:s2': 1 }`)行うと、plays 2・bestStars 3・best が `{ 'puzzle:s1': 3, 'puzzle:s2': 1 }`。
5. 星の低い結果を後から add しても、bestStars と best は下がらない。
