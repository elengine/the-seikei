## PU-13a:ホームのドラム設定の絵、「はい」「いいえ」

- **ドラム設定の絵**:管理者の指摘「羽の向きを逆にする。ドラム設定の遊ぶ画面と同じ向きに」。遊ぶ画面(T2c-04 で羽を左に開いた)と同じく、羽が**左上へ**登り、層が右に寄って積み上がる形にする(今の絵を左右反転した形)。テスト:羽の線の上の端の x が、下の端の x より小さい。
- **戻りますか**:「ホームに戻りますか」「お題の一覧に戻りますか」の確認は、問いかけなので、ボタン名を **「はい」(ok)「いいえ」(cancel)** にする(すべてのゲームと gameScreen)。ほかの確認(「続きから」「最初から」、「新しいお題を始めますか」など)は変えない。テスト:戻る確認のボタンの文字が「はい」「いいえ」。

## PU-13b:クリール立ての依頼書とボタン

- 管理者の指摘(依頼書):
  - 「型番の文字が無駄に小さい。型番と個数の間の余白が大きいので、コーンの絵の高さと同じくらいの文字の大きさに」→ 型番の文字の大きさを、コーンの絵の直径と同じ(例:絵 40px なら 36〜40px)にする。色は今の控えめな色のまま。
  - 「低いレベルで出している括弧書き『(1〜5本目)』は、あまり役に立たないのに高さを取っている」→ **括弧書きを無くす**(何本目かの表示と、繰り返しの行の「(9本目から同じ並びを 1 回)」の両方)。
  - 「繰り返しの表記が控えめすぎる」→「↻ 繰り返し × 2」を「**↻ 2回繰り返す**」に。文字を少し大きく(個数より小さく、型番より大きい程度。例 32px)、太字。
- 管理者の指摘(遊ぶ画面):
  - 「依頼書を見る」→「**依頼書**」。
  - 「依頼書」のボタンを、「ヒント」の**左**に移す(縦・横どちらの画面でも「依頼書」「ヒント」「確認」の1行)。
  - 「完了」→「**確認**」。
  - ヒントが使えないときの文:「n回確認すると使えます」→「**あと n 回確認に失敗すると使えます**」(1回目のときも「あと 2 回確認に失敗すると使えます」)。
  - ヒントが使えないときのお知らせの縦の位置を、**クリール(盤面)の中央**にする。`createGameFrame` の `notify` のお知らせを、盤面のカードの上下の中央に出す(糸割りもこの位置で使う)。
- テスト:依頼書の行に括弧書きが無い、繰り返しの行が「2回繰り返す」で太字のクラス、ボタンの並びと名前(「依頼書」「ヒント」「確認」の順)、ヒントの文、お知らせが盤面の中央(CSS のクラスか `top: 50%` の指定)。
- 確認:5つの大きさ・文字の大きさ最大で、操作欄と画面全体のスクロールが 0 のまま。

## PU-13c:チーズを引っぱるときの不具合

- 管理者の指摘:
  1. 「段ボールをスワイプしてもチーズが出てこないときがある。発現条件は不明」。
  2. 「スワイプで出てくるチーズは指より上に出る仕様だが、Fold 8 ではあまり上に出ない。iPhone ではちょうど良いので、Android 特有の問題かもしれない」。
- 1 の調べ方の例(原因を特定して報告に書く):指を置いてすぐ横に動かしたとき(箱の帯の横スクロールと取り合いになる:`touch-action`、`pointercancel`)、箱の端を押さえたとき(当たり判定)、2本目の指、前の引っぱりが終わる前の次の引っぱり。`pointercancel` が来たら、引っぱりを終わらせて箱に戻す処理があるか。原因ごとに、再現するテストを先に書いてから直す。
- 2 の直し方:指より上に出す量(`LIFT_PX` 40)を、チーズの大きさに合わせて決める。**チーズの下の端が、指の点より 24px 以上上**にくる(持ち上げる量 = チーズの半径 + 24px。数値は params)。Android の Chrome で上に出る量が小さく見える原因(例:チーズの位置を指の点ではなく要素の左上で合わせている、画面の拡大率、`clientY` と `pageY` の取り違え)も確かめ、報告に書く。
- テスト:持ち上げる量の計算(半径 + 24)、`pointercancel` で引っぱりが終わってチーズが箱に戻る、ほか原因ごとの再現テスト。
