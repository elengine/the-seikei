## 1. 目的と背景

尾州産地で個人経営の整経業(部分整経)を営んでいた父(引退済み・高齢)へのプレゼントとして、整経を題材にした iPad・スマホ向けの簡単なゲームを作る。

目的は次の3つ。

1. 父が昔の仕事を懐かしみながら、気軽に楽しめること。
2. 高齢の利用者が、説明なし、またはごく短い説明で遊べること。
3. 最終的に5つのゲームがひとつのアプリとしてまとまり、将来的に端末間で進行状況を共有できること。

## 2. 利用者

| 役割 | 人物 | 概要 |
|---|---|---|
| プレイヤー | 父 | 高齢。元・整経業。iPad と Android スマホを所有。ポケモンGO、オセロなどを日常的に遊んでおり、タップ・スワイプ操作には慣れている。 |
| 管理者 | さとし | 開発・配信・運用を担当。設定変更やデータ確認を行う。 |
| 家族(将来) | 家族 | 同期機能の導入後、図鑑に写真や思い出を追加できる(フェーズ6以降)。 |

最終形(フェーズ1〜6すべて)を前提に設計し、実装はフェーズ順に進める。各フェーズ完了時点で、それまでの機能だけで遊べる状態にする。

| フェーズ | 内容 | 主な要件 |
|---|---|---|
| P0 | 共通基盤(ホーム、設定、用語辞書、保存層、効果音、チュートリアル枠) | FR-C, DR |
| P1 | クリール立て | FR-G1 |
| P2 | ドラム巻き(糸継ぎを含む) | FR-G2 |
| P3 | ビーミング(糸継ぎを含む) | FR-G3 |
| P4 | 思い出の柄図鑑 | FR-G5 |

P0 の保存層は、P6 の同期を後から追加しても既存コードを変更せずに済む形で作る(DR 系)。

## 5. 題材の設定

### 5.1 工程(部分整経)

ゲームで扱う工程は次のとおり。呼び名はすべて用語辞書の初期値であり、変更可能。ゲームはこの工程順に並べる(v0.2 で変更。資料映像のキャプチャと管理者の説明による)。

1. **クリール立て**:依頼書に従い、格子状に並んだクリールの軸に、色と糸の種類の順番を間違えずにコーンを立てる。同じ色でも依頼によって太さ・撚り・素材などが違うため、依頼書に書かれた品番と、糸の入った段ボール箱の品番を突き合わせて見分ける。1色なら易しいが、柄物や、同じ色で品番が違う糸が混ざる場合は慎重さが要る。
2. **綾取り**:糸の並び順を保つために綾をとる。
3. **ドラム巻き**:クリールの各段から集めた糸を帯にまとめ、ドラム(桟を組んだかご状の胴)の区画へ帯ごとに所定の長さだけ巻く。巻き終えたら帯を切って端を留め、次の区画へ送る。作業者は糸の張りと切れを見ながら、足のペダルで速度を調整する。
4. **ビーミング**:巻き終えたドラムから、全幅の糸のシートをローラー経由でビーム(両端に穴の開いたつばを持つ)へ巻き返す。ここでも糸切れと張りに気をつける。
5. **糸継ぎ**:ドラム巻き・ビーミングの途中で糸が切れると機械が止まり(赤ランプが点く)、何百本もの糸の中から切れた場所を見つけて結び直す。単独の工程ではなく、3・4の中で起きる出来事として扱う。

### 5.2 舞台

| 項目 | 設定 |
|---|---|
| 場所 | 尾州産地(作中でも「尾州」とだけ表現し、具体的な地名は出さない) |
| 年代 | 1967年〜2004年 |
| 産地 | 尾州。ウールの服地(梳毛・紡毛)を中心とした想定。**裏付けは TBD-02** |
| 機械 | 部分整経機2台(1号機・2号機)。機体色はうぐいす色(資料映像では灰みの緑。最終的な色味は父に確認) |
| お店 | 屋号は設定で入力可能(FR-C-03) |

### 5.3 表現上の方針

- 産地の衰退や廃業など、つらい記憶につながりうる出来事はゲームの要素として扱わない。
- 失敗しても大きく減点されたり、ゲームオーバーになったりしない。倒産などの概念も設けない。

## 6. 機能要件

### 6.1 共通(FR-C)

| ID | 要件 | フェーズ |
|---|---|---|
| FR-C-01 | ホーム画面から各ゲームと図鑑を選べる。未実装のゲームは表示しないか「準備中」とする。 | P0 |
| FR-C-02 | どの画面からも、1回のタップでホームへ戻れる。ゲーム途中で戻る場合は確認を出す。 | P0 |
| FR-C-03 | 設定画面で、プレイヤー名と屋号を入力できる。入力値はゲーム内の表示(のれん、注文書など)に使う。 | P0 |
| FR-C-04 | 画面に出る整経用語はすべて用語辞書から読み込む。設定画面で各用語を編集でき、初期値に戻せる。 | P0 |
| FR-C-05 | 設定画面で、文字サイズ(大/特大)、効果音のオン・オフ、音量を変更できる。 | P0 |
| FR-C-06 | 各ゲームに、絵と短い文で遊び方を示すチュートリアルがある。初回は自動表示し、以降はいつでも開ける。 | P0 |
| FR-C-07 | 遊んでいる途中の状態は自動で保存され、アプリを閉じても続きから再開できる。 | P0 |
| FR-C-08 | 成功時は効果音と分かりやすい演出でほめる。失敗時も責める表現は使わない。 | P0 |
| FR-C-09 | 管理者向けに、データの書き出し(ファイル保存)と読み込みができる。端末の買い替えや不具合時の保険とする。 | P0 |

### 6.2 クリール立て(FR-G1)

| ID | 要件 |
|---|---|
| FR-G1-01 | 依頼書(品番・色・本数の並び)と、格子状のクリールの軸を表示する。 |
| FR-G1-02 | 品番の書かれた段ボール箱からコーンを選び、軸をタップして立てる。はずす・立て直しができる。 |
| FR-G1-03 | 同じ色でも品番が違う糸があり、依頼書の品番と箱の品番を突き合わせて見分ける。色だけに頼らず、品番の文字と色の記号を併記する(NFR-U-05)。 |
| FR-G1-04 | 立てたコーンは、帯の並びとして画面にすぐ反映され、クリールの位置と帯の何本目かの対応が分かる。 |
| FR-G1-05 | 「たしかめる」で判定し、間違った位置を示す。何度でもやり直せ、間違いは星の数にだけ反映する。 |
| FR-G1-06 | 正しく立て終えると、帯の並びから生地の見本を表示し、柄を図鑑に登録する。 |
| FR-G1-07 | お題はデータで追加できる。1色の易しいものから始め、段数・色数・糸の種類が増える順に並べる。 |

### 6.3 ドラム巻き(FR-G2)

| ID | 要件 |
|---|---|
| FR-G2-01 | 帯にまとめた糸を、ドラムの区画へ帯ごとに巻く。ドラムは桟を組んだかご状の胴として描く。 |
| FR-G2-02 | 巻く速さは画面のペダルで調整する。ペダルは押し続けなくても踏み込み量を保てる操作とする。 |
| FR-G2-03 | 速く巻くほど張りが上がり、適正範囲を超えると糸が切れやすくなる。コーンの糸が減るにつれて張りが変わる。 |
| FR-G2-04 | 糸が切れると赤ランプが点いて機械が止まる。切れた糸を探し、切れ端同士を結ぶと再開できる(糸継ぎ)。 |
| FR-G2-05 | 1本の帯を巻き終えたら、帯を切って留め、次の区画へ送る。 |
| FR-G2-06 | 全帯を巻き終えたら、ドラムの表面を帯ごとの出来で描き分け、点数をつける。 |
| FR-G2-07 | 張りが範囲を外れても止めない(切れやすくなるだけ)。時間制限はない。 |

### 6.4 ビーミング(FR-G3)

| ID | 要件 |
|---|---|
| FR-G3-01 | 巻き終えたドラムから、全幅の糸のシートをビームへ巻き返す。ビームは両端に穴の開いたつばを持つ形で描く。 |
| FR-G3-02 | 操作はドラム巻きと同じペダル。全幅が動くため切れる糸の候補は多いが、工程は短い。 |
| FR-G3-03 | 糸切れの対応はドラム巻きと同じ(FR-G2-04)。 |
| FR-G3-04 | 巻き終えたら満巻きのビームを見せて完了とする。 |
| FR-G3-05 | 単独で遊ぶ場合は巻き終えたドラムから始める。経営シミュレーションでは、その仕事のドラムの出来を引き継ぐ。 |

### 6.5 整経屋の一日(FR-G4)

| ID | 要件 |
|---|---|
| FR-G4-01 | 機屋から注文(本数、長さ、柄、納期)が届く。機屋の名前は架空とする。 |
| FR-G4-02 | 注文を1号機・2号機のどちらかに割り当てる。 |
| FR-G4-03 | 割り当てた仕事は、クリール立て・ドラム巻き・ビーミングのミニゲームとして遊ぶ。「おまかせ」を選ぶと自動で完了させられる。 |
| FR-G4-04 | ターン制(1日単位)で進み、リアルタイムに急かされない。 |
| FR-G4-05 | 仕事の出来に応じて売上と評判が増える。減ることはあっても、倒産やゲームオーバーはない。 |
| FR-G4-06 | 年代が1967年から少しずつ進み、注文される柄や生地が変化する。 |
| FR-G4-07 | 仕上げた注文の柄は図鑑に登録される。 |

### 6.6 思い出の柄図鑑(FR-G5)

| ID | 要件 |
|---|---|
| FR-G5-01 | 集めた柄を一覧で表示する。未入手の柄はシルエット等で示す。 |
| FR-G5-02 | 各ゲームから柄を登録できる共通の仕組みを持つ。 |
| FR-G5-03 | 各柄に名前、年代、短い説明を表示する。 |
| FR-G5-04 | 柄データは、コードを変えずにデータの追加だけで増やせる。 |
| FR-G5-05 | (P6)家族が写真と一言メモを図鑑に追加できる。 |

### 6.7 同期(FR-S、フェーズ6)

| ID | 要件 |
|---|---|
| FR-S-01 | iPad とスマホで、進行状況・図鑑・設定を共有できる。 |
| FR-S-02 | 最初はログインなし(匿名)で遊び始められ、同期を使うときにアカウントまたは引き継ぎコードで紐付ける。 |
| FR-S-03 | 同期はオンライン時に自動で行う。オフライン中の変更は、つながった時点で反映する。 |
| FR-S-04 | 同期に失敗しても、端末内のデータで遊び続けられる。 |
| FR-S-05 | 管理者は父の記録を閲覧できる(父の同意のうえで)。 |

## 7. 非機能要件

### 7.1 使いやすさ・アクセシビリティ(NFR-U)

| ID | 要件 |
|---|---|
| NFR-U-01 | 本文の文字サイズは「大」で 20px 以上、「特大」で 24px 以上とする。 |
| NFR-U-02 | タップできる部品は 60×60px 以上、隣り合う部品の間隔は 8px 以上とする。 |
| NFR-U-03 | 文字と背景のコントラスト比は 4.5:1 以上とする。 |
| NFR-U-04 | ダブルタップ、ピンチ、複数本指の操作を必須にしない。長押し(押し続ける操作)も必須にしない。 |
| NFR-U-05 | 色だけで情報を区別させない(色覚の個人差・加齢による見え方の変化への配慮)。 |
| NFR-U-06 | 画面の文言はやさしい日本語で、1画面の説明は3行程度までとする。 |
| NFR-U-07 | iPad は横向き、スマホは縦向きを推奨とし、どちらの端末でも回転しても進行が失われない。詳細は TBD-04。 |
| NFR-U-08 | 意図しない画面の拡大・スクロール・引っ張って更新を起こさない。 |

### 7.2 性能(NFR-P)

| ID | 要件 |
|---|---|
| NFR-P-01 | Wi‑Fi 環境で、起動からホーム画面表示まで3秒以内。2回目以降はより速いこと。 |
| NFR-P-02 | ゲーム中のアニメーションは 30fps 以上を維持する(目標 60fps)。 |
| NFR-P-03 | 配信物の合計サイズは 20MB 以内を目安とする。 |

### 7.3 可用性(NFR-A)

| ID | 要件 |
|---|---|
| NFR-A-01 | 一度読み込んだ後は、通信が切れていても全ゲームを遊べる(P6 の同期を除く)。 |
| NFR-A-02 | 新しい版を公開したとき、父が特別な操作をしなくても次回起動時までに反映される。反映時に保存データは失われない。 |

### 7.4 互換性(NFR-X)

| ID | 要件 |
|---|---|
| NFR-X-01 | 父の端末の iPadOS(Safari)と Android(Chrome)で動作する。対象バージョンは TBD-03。 |
| NFR-X-02 | ホーム画面に追加したアイコンから、アドレスバーのない全画面表示で起動する。 |

### 7.5 保守性・実装体制への適合(NFR-M)

| ID | 要件 |
|---|---|
| NFR-M-01 | タスク仕様書はリポジトリ内に置き、Discord では定型の短い指示(仕様書のパスを示す)だけを送る。1タスクで変更するファイルは原則1〜4個(テストを含む)に収める。 |
| NFR-M-02 | タスク仕様書には、目的、関連要件ID、変更ファイル、入出力(インターフェース)、完了条件、テスト方法を必ず書く。 |
| NFR-M-03 | 1ファイルの長さは 300 行程度を上限の目安とする。 |
| NFR-M-04 | 自動テストをコマンド1つで実行でき、実装担当(LLM)が自分で合否を確認できる。 |
| NFR-M-05 | ゲーム同士は直接依存せず、共通基盤のインターフェースだけに依存する。 |
| NFR-M-06 | お題、柄、注文、用語などの内容データはコードと分離し、データの追加だけで増やせる。 |

### 7.6 セキュリティ・プライバシー(NFR-S)

| ID | 要件 |
|---|---|
| NFR-S-01 | P5 までは外部へデータを送信しない。アクセス解析も入れない。 |
| NFR-S-02 | P6 では、父のデータは本人と管理者(および許可した家族)だけが読み書きできる。 |
| NFR-S-03 | API キー等の秘密情報をリポジトリに含めない。クライアントに置いてよいのは公開前提のキーのみとする。 |

### 7.7 コスト(NFR-C)

| ID | 要件 |
|---|---|
| NFR-C-01 | 運用費は0円。利用する外部サービスは無料枠の範囲に収め、上限を超えても課金されない設定にする。 |
| NFR-C-02 | 無料枠の休止・停止条件(一定期間未使用での停止など)が父の利用頻度で問題にならないことを確認する(TBD-01)。 |

## 8. データ要件(DR)

P6 の同期を後から追加してもデグレを起こさないための要件。**P0 から適用する。**

| ID | 要件 |
|---|---|
| DR-01 | ゲーム・画面は保存先を直接扱わず、共通の保存インターフェースだけを通して読み書きする。P0 では端末内保存の実装のみ作り、P6 で同期つき実装を追加する。 |
| DR-02 | 保存する記録には、ID(UUID)、作成日時、更新日時(UTC)、更新した端末のID を持たせる。 |
| DR-03 | 削除は物理削除せず、削除日時を記録する(同期時に削除を伝えるため)。 |
| DR-04 | 保存データ全体にスキーマのバージョン番号を持たせ、版が上がったときの移行処理を用意する。移行処理にはテストを付ける。 |
| DR-05 | 保存インターフェースに対する共通テスト(契約テスト)を作り、端末内保存と同期つき保存の両方が同じテストに合格することを完了条件とする。 |
| DR-06 | 端末間で内容が食い違った場合の扱いを、データの種類ごとに次のとおり定める。 |

DR-06 の競合ルール(初期案):

| データ | ルール |
|---|---|
| 図鑑の入手状況 | 両端末の和(どちらかで入手していれば入手済み) |
| ベストスコア・評判の最高値 | 大きい方 |
| 経営シミュレーションの進行中データ | 更新日時が新しい方 |
| 設定・用語辞書 | 項目ごとに更新日時が新しい方 |
| 家族が追加した写真・メモ | 両方残す |
