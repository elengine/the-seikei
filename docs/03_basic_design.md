### 1.2 遷移

```
起動 ─▶ 起動処理(移行・永続化要求・音の準備) ─▶ ホーム
ホーム ─▶ 各ゲーム ─▶ (途中保存があれば「つづきから/はじめから」) ─▶ ゲーム ─▶ 結果 ─▶ もう一度 / ホーム
ホーム ─▶ 図鑑 ─▶ 図鑑の詳細
ホーム ─▶ 設定 ─▶ 呼び名の変更
設定 ─▶ 管理者メニュー(数字4桁の入力で開く)
```

- 各ゲームの初回起動時は、チュートリアルを自動で表示する(FR-C-06)。
- 管理者メニューは、設定画面の最下部に小さめのボタンで置き、4桁の数字(初期値 `1967`、創業の年)を入れたときだけ開く。父が誤って開かないための措置であり、セキュリティ目的ではない。

### 1.3 画面の共通枠

ゲーム画面は次の枠を共通で使う(`core/ui/GameFrame`)。

- 上部の帯:左に「もどる」、中央にゲーム名、右に「あそびかた」。
- 盤面:Canvas。横長レイアウトでは左、縦長レイアウトでは上(02_architecture 9章)。
- 操作と情報の欄:ボタン、進み具合、メッセージ。横長では右、縦長では下。
- 「もどる」を押すと確認ダイアログを出す。「ホームにもどる」「つづける」の2択で、「はい/いいえ」は使わない。戻る前に途中保存する。

## 2. デザイン

### 2.1 色

コントラスト比は背景色(生成り)に対する値。文字に使う色はすべて 4.5:1 以上(NFR-U-03)。

|---|---|---|---|

| sumi(墨) | `#2B2A24` | 本文 | 12.98 |
| sumiSub | `#5A574C` | 補足の文字 | 6.53 |
| machineDark | `#4F5B47` | 主ボタンの地(文字は白で 7.19) | 6.49 |
| machine(機体の灰緑) | `#8C9A7E` | 整経機・クリールの機体、飾り。文字には使わない | 2.69 |
| machineLight | `#A9B39C` | 機体の明るい面。文字には使わない | 1.97 |
| wood(桟) | `#8A5A3C` | ドラムの桟。文字には使わない | ― |
| steel(ローラー) | `#B8BEC4` | ローラー、ビームの芯まわり。文字には使わない | ― |
| shu(朱) | `#B03A2E` | 糸切れ、要注意の表示(文字は白で 6.02) | 5.43 |
| ai(藍) | `#2F4A6D` | 副ボタン、選択中の枠 | 8.16 |
| white | `#FFFFFF` | ボタン上の文字 | ― |

- 機体の色は、父が「うぐいす色」と呼ぶ実機に近い灰みの緑を、資料映像から推定したもの。父に見てもらって調整する(値は tokens.ts の1か所で変えられる)。
- 暗い配色(ダークモード)には対応しない。端末の設定にかかわらず上の配色で表示する。
- 点滅は使わない。強調は色の変化、ゆっくりした揺れ、記号の併記で行う。

### 2.2 文字

| 種類 | 大(既定) | 特大 |
|---|---|---|
| 本文 | 20px | 24px |
| ボタンの文字 | 22px | 26px |
| 見出し | 28px | 34px |
| 数字の表示(メーター等) | 32px | 38px |

- 書体は端末標準の日本語ゴシック(`"Hiragino Sans", "Noto Sans JP", sans-serif`)。太さは本文 500、ボタンと見出し 700。
- 文字サイズは CSS 変数で切り替え、Canvas 内の文字も同じ定数から計算する。

### 2.3 大きさと間隔

| 項目 | 値 |
|---|---|
| ボタンの最小サイズ | 高さ 64px、幅 120px(アイコンだけのボタンは 64×64px) |
| 部品の間隔 | 12px 以上 |
| 角の丸み | 12px |
| 盤面内のタップ判定 | 見た目より広くとり、最低 64px 四方 |

### 2.4 動き

- 通常の動きは 300〜600ms で、急な動きをしない。
- 成功時の演出は 1.5 秒程度で、演出中もボタンは押せる。
- 画面の拡大縮小、引っ張って更新、長押しメニュー、文字選択を無効にする(NFR-U-08)。

| 部品 | 内容 |

| TutorialOverlay | 1ページに絵(Canvas で描く)と3行以内の文。「つぎへ」「はじめる」 |

自動で消える表示(トースト)は使わない。メッセージは利用者が閉じるか、次の操作まで残す。

## 3. データ型

`core/domain/types.ts` に置く。ゲーム固有の状態型は各ゲームの `logic.ts` に置く。

```ts
// ---- 糸と柄 ----
type ColorId = string;                 // 'kon', 'kuro' など
interface YarnColor {
  id: ColorId;
  name: string;                        // 表示名(例:紺)
  hex: string;                         // 描画色
  symbol: string;                      // 色覚配慮の記号(例:●)
}

type YarnTypeId = string;              // 'kon-a' など
interface YarnType {
  id: YarnTypeId;
  color: ColorId;
  hinban: string;                      // 品番(例:'W-4812')。箱と依頼書に書かれ、同じ色の糸を見分ける手がかり
  spec: string;                        // 糸の説明(例:'ウール 2/48 甘撚り')。図鑑や箱の側面に小さく表示
}
interface StripeRun { yarn: YarnTypeId; count: number; }   // 同じ糸が count 本続く
type StripePlan = StripeRun[];                              // 帯の並び(1リピート分)

interface Pattern {
  id: string;                          // 'pinstripe-navy-01' など
  name: string;                        // 表示名
  plan: StripePlan;
  weft: ColorId;                       // 緯糸の色(見た目の生成に使う)
  era: { from: number; to: number };   // 登場する年代(西暦)
  description: string;                 // 図鑑の説明(3行以内)
  difficulty: 1 | 2 | 3;
}

// ---- 仕事 ----
type MachineId = 1 | 2;
interface JobSpec {
  orderId: string;
  patternId: string;
  ends: number;                        // 総本数(表示用)
  lengthM: number;                     // 整経長(m)
  sections: number;                    // 帯の数
  difficulty: 1 | 2 | 3;
}

// ---- 結果 ----
interface GameResult {
  gameId: GameId;
  mode: 'standalone' | 'job';
  stars: 1 | 2 | 3;
  stats: Record<string, number>;       // ゲームごとの成績(継いだ本数など)
  unlockedPatternIds: string[];
  finishedAt: string;
}
```

### 3.1 保存するデータ

`Rec<T>`(02_architecture 5.2)の `data` に入る型。ID は固定キーまたは UUID。

| コレクション | ID | data の型 |
|---|---|---|
| settings | `'main'` | `{ playerName: string; shopName: string; fontScale: 'large' \| 'xlarge'; soundOn: boolean; volume: number; tutorialSeen: Partial<Record<GameId, boolean>> }` |
| terms | 用語キー | `{ value: string }`(上書きした用語だけ保存) |
| zukan | patternId | `{ obtainedAt: string; source: GameId; count: number }` |
| records | gameId | `{ bestStars: number; plays: number; best: Record<string, number> }` |
| sessions | gameId | `{ state: unknown; savedAt: string }`(ゲームの途中保存) |
| shop | `'main'` | 経営シミュレーションの状態(6.4) |

- settings の初期値:playerName `''`、shopName `'整経所'`、fontScale `'large'`、soundOn `true`、volume `0.7`。
- settings・terms は項目ごとの新しい方を採る競合ルールのため、settings は `Rec` 全体ではなく項目ごとの更新日時を data 内に持つ(`_updated: Record<string, string>`)。

### 4.1.1 糸の種類(初期値)

- 同じ色でも依頼によって太さ・撚り・素材などが違い、段ボール箱と依頼書の品番で見分ける(TBD-07 解決)。
- 品番は「英字1文字 + ハイフン + 数字4桁」(例:`W-4812`)とする。架空の番号であり、実在の品番は使わない。
- 各色に1種類ずつ用意し、同じ色で品番が違うものとして紺・灰・チャコールに2〜3種類を加える。
- 上級のお題向けに、数字の並びが似た品番(`W-4812` と `W-4821` など)を用意する。やさしいお題では使わない。

### 4.2 柄の種類(初期案)

紳士服地で一般的な縦縞を中心にする。具体的な柄データと年代づけは P4 の内容作成で行い、そのとき当時の尾州の実情を裏付ける(TBD-02)。

- 無地(1色)
- ピンストライプ、ヘアライン(細い線)
- チョークストライプ(ぼかした線)
- オルタネートストライプ(2色の線が交互)
- シャドーストライプ(同系色の濃淡)
- ブロックストライプ(太い縞)

## 6. 各ゲームの仕様

### 共通の約束

- ルールは `logic.ts` に `init(params, seed) → State` と `reduce(State, Action) → State` として書く。時間の経過は `{ type: 'tick', dtMs }` で表し、描画側が requestAnimationFrame から送る。
- 乱数は State に持たせた種(seed)から生成する(`core/clock` の擬似乱数)。同じ種と同じ操作なら同じ結果になり、テストと途中再開が確実になる。
- 途中保存は State をそのまま保存する。保存の時機は、主要な操作の後(1秒に1回まで)と、アプリが裏に回ったとき。
- 数値の初期値は各ゲームの `params.ts` に置く。
- 盤面の論理座標は 1000×750(横長)を基本とし、縦長レイアウトでも同じ座標で描いて縮小する。
- 機械の見た目は資料映像に合わせる:機体は灰みの緑、ドラムは茶色の桟を組んだかご状の胴、ビームは両端に穴の開いたつば、ローラーは銀色。

### 6.0 共有の仕組み(`core/mechanics`)

ドラム巻きとビーミングの両方で使う。どちらも純粋関数の部品として作り、各ゲームの reducer から呼ぶ。

#### 6.0.1 ペダルと張り(`pedal.ts`)

| 値 | 意味 |
|---|---|
| pedal | 踏み込み量 0〜100。画面のペダルを上下に動かして決め、指を離してもその位置を保つ |
| speed | 巻く速さ。pedal に比例(0 で停止) |
| tension | 張り 0〜100 |

- tension = 基準値 + speed による上昇 + 糸量による変化 + ぶれ。
  - speed による上昇:速いほど張りが上がる。
  - 糸量による変化:仕事の進み具合(0〜1)に応じて、基準値が少しずつ上がる(コーンの糸が減ると張りが変わる)。
  - ぶれ:乱数で少しずつ動く小さな値。
- 適正範囲(params)の中なら「よい巻き」、上を外れると糸が切れやすくなる、下を外れると巻きがゆるむ(出来が下がる)。
- 係数はすべて params に置く。「ゆっくり踏めば必ず適正範囲に入る」ように係数を決める(遅く巻けば失敗しない、という安心を保証する)。

#### 6.0.2 糸切れと糸継ぎ(`breakage.ts`)

- 運転中、一定時間ごとに「切れるかどうか」を判定する。確率は張りが適正範囲の上を外れているほど高く、範囲内ではごく低い(params)。
- 切れたら:機械が止まり(speed 0。ペダルは効かない)、赤ランプを点灯する(点滅はしない)。メッセージ「糸が切れました。切れた糸をさがして、つないでください」。
- 切れた糸は、盤面上の糸のうち1本を乱数で選ぶ。その糸は途中で切れ、両側の切れ端が垂れて描かれる。
- 見つけやすさは難易度で変える。

| 難易度 | 切れた糸の見せ方 |
|---|---|
| やさしい | 切れた糸を朱色で描き、ゆっくり揺らす |
| ふつう | 色は変えず、切れ端が垂れているのが分かる程度 |
| むずかしい | 切れ端の垂れが小さく、よく見ないと分からない |

- 結ぶ操作は2手:(1) クリール側の切れ端をタップ、(2) 反対側の切れ端をタップ。2手目で結ぶ演出(1秒、効果音 knot)の後、ランプが消え、ペダルが効くようになる。
- 判定幅は見た目より広くとる(最低 64px 四方、NFR-U-02)。違う場所をタップしたら「その糸はだいじょうぶです」と表示するだけで、減点しない(回数は記録)。
- 1手目の後に別の糸を押した場合は、1手目をやり直す扱いにする。
- 同時に切れるのは1本だけ。

### 6.1 クリール立て(G1、FR-G1)

**画面**

- 上部(横長では左上):依頼書。帯の並びを「品番・色の記号・色名・本数」の表で示す(例:「W-4812 ● 紺 × 6」「W-2200 ○ 白 × 1」)。その下に、完成すればこうなる、という帯の見本(FabricPreview)。
- 盤面:格子状のクリール。灰緑の枠に、段(横の行)ごとに軸が並ぶ。立てたコーンは色と色の記号で描く(品番の表示は下の「糸の種類と品番」による)。
- 盤面の下:「いまの帯の並び」。立てたコーンを帯の順に1列に並べて表示し、空いている軸は点線の枠で示す。
- 操作欄:品番の書かれた段ボール箱の一覧、「はずす」「たしかめる」「ヒント」。

**クリールの位置と帯の順番**

帯の何本目になるかは「上の段から順に、各段は左から」とする(文章を読む順)。やさしい・ふつうのお題では各軸に小さく番号を表示し、むずかしいお題では各段の先頭の番号だけを表示する。

**糸の種類と品番**

- 同じ色でも依頼によって太さ・撚り・素材が違う。見分ける手がかりは品番で、依頼書と段ボール箱の両方に書かれている。遊ぶ人は依頼書の品番と箱の品番を突き合わせてコーンを取る。
- 糸の箱は段ボール箱の絵とし、正面に品番を大きく(`--fs-number`)、その下に色の記号と色名を書く。
- 軸に立てたコーンは、同じ色なら見た目では区別できない(実際と同じ)。そのため:
  - 段階1〜3のお題では、立てたコーンの下に品番を小さく表示する。
  - 段階4以降では表示せず、立てたコーンをタップしたときだけ品番を吹き出しで見せる(はずす・立て替えを選んでいないとき)。
- 依頼書の表は「品番・色の記号・色名・本数」の列とし、今選んでいる箱と同じ品番の行を藍の枠で示す(突き合わせを助ける)。

**状態**:お題、軸ごとの YarnType(未配置は null)、選択中の箱、確かめた回数、間違いの位置、ヒント使用回数、done。

**流れ**

1. 箱を選ぶと藍の枠で囲まれる。以後、空いている軸をタップするとその箱のコーンが立つ(選んだ箱は選び直すまで保持)。
2. すでにコーンが立っている軸をタップすると、選んでいる箱のコーンに立て替える。「はずす」を選んで軸をタップすると空にする。
3. 「たしかめる」で判定。間違った軸と空の軸に朱の✕を表示する。何度でもやり直せる。
4. 確かめて2回間違えたら「ヒント」を押せるようにする。ヒントは間違っている軸の1つを正しいコーンにする。
5. 全部正しければ done。帯の見本が織り上がる演出を出し、柄を図鑑に登録する。

| 段階 | クリール | 内容 |

| 2 | 1段×8軸 | 2色の縞 |
| 3 | 2段×8軸 | 2〜3色の縞 |
| 4 | 2段×10軸 | 同じ色で品番が違う糸を含む |
| 5 | 3段×10軸 | 色と品番の組み合わせ。似た品番を含む |

**採点**:確かめた回数が1回(一発正解)で星3、2〜3回で星2、それ以上またはヒント使用で星1。

**仕事モード**:JobSpec.patternId の柄から、クリールの大きさに合わせた並びを作ってお題にする。

### 6.2 ドラム巻き(G2、FR-G2)

**画面**:盤面の左にクリールから帯へ集まる糸、中央に帯を送る台とレール、右にかご状のドラム。ドラムの端には長さの目盛り盤と赤ランプ。操作欄に、ペダル(縦長の大きなつまみ。つまみは 64px 以上)、張りのメーター(適正範囲を緑の帯と「ちょうどよい」の文字で表示)、巻いた長さ、帯の番号(例「3 / 6 本目の帯」)。

**状態**:`phase: 'ready' | 'winding' | 'broken' | 'tying' | 'cutting' | 'done'`、帯の番号、帯ごとの巻いた長さ、ペダルと張りの状態(6.0.1)、糸切れの状態(6.0.2)、帯ごとの「適正範囲に入っていた時間の割合」、乱数の種。

**流れ**

1. 「巻きはじめる」で winding。ペダルを踏み込むと巻き始める。
2. 巻いている間、張りと糸切れは 6.0 の仕組みで動く。切れたら broken → 糸継ぎ(2手)→ winding。
3. 帯が所定の長さに達したら自動で止まり、cutting。「帯を切って留める」ボタンを押すと、切って留める演出の後、台が次の区画へ送られ、次の帯を巻き始められる。休憩を兼ねる。
4. 全部の帯を巻いたら、ドラムの表面を帯ごとの出来で描き分ける(出来が悪い帯は表面が波打つ)。done。

**難易度**

| params | やさしい | ふつう | むずかしい |
|---|---|---|---|
| 帯の数 | 3 | 5 | 7 |
| 適正範囲 | 30〜70 | 38〜62 | 44〜56 |

**結果として残すもの**:帯ごとの出来(0〜1)の配列。仕事モードではビーミングに引き継ぐ。

**仕事モード**:JobSpec.sections を帯の数に、difficulty を難易度に使う。

### 6.2a 糸割り(ワインダー):改訂案(2026-10-04、確認役。管理者の確認待ち。下の元の 6.2a より優先)

> 出どころ:お父さんへの確認(2026-10-04、管理者経由、会話)「ワインダーは必要な状況になったときだけ使った。(1)ドラムに巻いている途中でクリールのコーンの糸が無くなったとき、残っているコーンの長さを計算して、長く残っているものをワインダーにかけ、糸を継ぎながら空のコーンに巻いて必要な本数にする(例:残りが6本で8本要るなら2本作る)。(2)納品されたチーズの数が足りないとき、チーズを立てて空のコーンに半分だけ巻いて数を増やす(例:100個を200個に。同時に何本もかけられるので、できるだけ同時に巻く)」と、管理者が示した機械の写真(リポジトリには入れない)。

**考え方**:ワインダーは「困ったときに助ける」機械。遊びは**場面(困りごと)から始まり**、計算して、機械に段取りよくかけて、必要な本数をそろえる。手応えの中心は「長さを計算する」「足りなくならないよう割り振る」「同時にかけて手早く済ませる」。

**機械の見た目(写真の特徴)**:正面から見た横に長い機械。緑の枠。**上の段**に元の糸(大きなコーン・チーズ)を紙の上に立て、黄色い糸道(ガイド)を通す。**下の段**に、銀色の溝の付いた胴(糸を左右に振る)が横一列に並び、その上に、緑の腕で押さえた空のコーン(紙の芯。巻くと太る)が乗る。腕の先の白い握りを下ろすと巻き始め、上げると止まる。口は横一列に最大12。

**2つの場面**(お題の種類。一覧で分ける)

1. **チーズを分ける**(やさしい。レベル1〜2)
   - 依頼書:「チーズが 6 個届きました。クリールには 12 本要ります。1本あたり 2,400m 以上」。
   - 手順:チーズを上の段に、空のコーンを下の段に、口の数だけ置く → カウンターをチーズの長さの**半分**に合わせる(チーズの長さは、重さから計算。レベル1 は画面が出す)→ 白い握りを下ろして同時に巻く → カウンターで自動で止まる。チーズが 12 個より多い口を要るときは、2回に分けてかける(段取り)。
   - うまくいかない例:半分より多く巻くと、元のチーズのほうが足りなくなる(朱の印)。少なすぎると、作ったコーンが足りない。
2. **足りないコーンを作る**(むずかしい。レベル3〜5)
   - 依頼書:「ドラムにあと 1,200m 巻きます。クリールには 8 本要りますが、残っているコーンは 6 本です」。6 本のコーンは、残りの長さ(重さ)がばらばら。
   - 手順:6 本を量って、残りの長さを出す → **1,200m より多く残っているぶん(余り)**を、空のコーンに巻き取る段取りを考える。1 本の余りで足りなければ、途中で次のコーンの糸を**継いで**続ける(お父さんの「糸を継ぎながら」)。元のコーンは 1,200m 以上を残さないといけない(残さないと、そのコーンが足りなくなる)。
   - カウンターは、元のコーンごとに「取ってよい長さ」に合わせる。そこで止まったら、次の元のコーンに替えて糸を継ぎ、続きを巻く。
   - うまくいかない例:取りすぎて元のコーンが 1,200m を割る(朱の印「足りなくなります」)/作ったコーンが 1,200m に届かない。

**計算**(ゲームの中の決まり。数値は `params.ts`):長さ(m)= (重さ − 紙の芯の重さ)(g)× 番手の数(双糸 2/48 なら 24)。レベルが上がるほど画面の手伝いを減らす(レベル1:長さを画面が出す、レベル2:式を出す、レベル3〜4:式の形だけ、レベル5:重さだけ)。電卓はドラム設定と同じものを使う。

**操作**:箱から元の糸・空のコーンを引っぱって口に置く(クリール立てと同じ操作)。はかりへ引っぱると重さが出る。カウンターは「+1000」「+100」「+10」「−10」「−100」「−1000」(m)。白い握りは口ごとに押して下ろす・上げる。「全部下ろす」ボタンもある(同時に巻く)。糸が無くなった口・継ぐ口は、その口を1回押して継ぐ(ドラム巻きと同じ)。

**採点**:①足りない本数が 0 か(作ったコーン・元のコーンとも、決められた長さ以上)②余分に巻いた量(少ないほど良い)③かけた回数(同時にかけて少ない回数で済ませるほど良い)。星3:足りないもの 0、余分 5% 以内、かけた回数が最少。成績欄にそれぞれを出す。時間の制限は無い。

**置き場所**:ホームのカードで、クリール立ての前(「準備中」の「糸割り」を置き換える)。名前「糸割り」(呼び名の変更の対象)。

**管理者の回答(2026-10-04、会話)**:2つの場面の形と、置き場所(クリール立ての前)は了承。開発した結果を見て改善する。作業のしかた:「コーンに巻く量をあらかじめ計算して、巻き始めたあとはメーターを見て、予定していた量になったら停止する」。数値は日本の情報を調べて決める。

**日本の情報で確かめたこと**(2026-10-04、確認役が調べた)

- 整経の前に、整経の長さに応じた糸量を巻いたコーンを用意する作業を「小割り」と呼ぶ。1個の満巻きから、少量巻きのコーンを何個も作る専用のワインダー(小割専用分割機。紙の芯はテーパーのコーン)もある。→ お父さんの「糸割り」と同じ作業。
- ワインダーは、糸の長さをメーター(カウンター)で数える。新しい機械には「各錘定長カウンター」(口ごとに決めた長さで自動で止まる)がある。設定は最大 10,000m の例。巻く速さは 50〜300m/分 の例。
- 写真の機械のような溝付きの胴(綾振りドラム)は、1本の軸で全部の口を回すので、**どの口も同じ速さで巻く**。止めるのは口ごと(握りを上げて、コーンを胴から離す)。
- 毛番手は「1g で何 m か」。長さ(m)= 正味の重さ(g)× 番手(双糸 2/48 は 24、単糸 1/48 は 48)。

**これを受けて決めたこと**

- **メーターは機械に1つ**(m の数字と、針の丸い目盛り盤)。「巻き始める」で 0 から数える。全部の口が同じ速さで巻くので、メーターの数字 = 各口がそのとき巻いた長さ(途中で止めた口・後から始めた口は、その口の上に小さく「1,240 m」と出す。レベル1〜3 だけ)。
- **止めるのは手で**(お父さんのやり方):予定の量に届いたら、その口の白い握りを押して上げる。「全部止める」ボタンもある。自動で止まる機能は付けない(古い機械。あとで「定長」を付けたくなったら params で足せるようにする)。
- **巻く速さ**:実際は 50〜300m/分だが、そのままでは長いので、ゲームの中では時間を縮める(1,000m を約 5 秒。params)。レベル1〜2 はゆっくり、レベル5 は速い。「低速」に落とすボタンを付ける(止めどころの手前で落とすと合わせやすい)。
- **計算の手伝い**:予定の量を先に計算して、依頼書の「予定」の欄に書き込む(この値がメーターの目印になる。レベル1〜2 は目盛り盤に予定の印が出る、レベル3 以上は出ない)。
- **止めたときの誤差**:予定より少ない → 作ったコーンが足りない(朱)/多い → 元のコーンが足りなくなる、または余分(朱か注意)。許す幅は 2%(params)。

**決まっていないこと**(推測で決める。遊んで調整):メーターの目盛り(1周 1,000m)、紙の芯の重さ(20g)、ゲームの中の速さ。

### 6.2a 糸割り(G6、FR-G6、P2b。元の下書き。上の改訂案に置き換える)

> 保留(2026-09-30、管理者、会話):糸割りには「ワインダー」という機械を使っていたことが分かった。詳細は管理者が調査中。下の「糸割り機」の見た目と動きは、調査結果に合わせて見直す。

> 出どころ:管理者の説明と回答(2026-09-30、会話)、記事「dig-it.media/2nd/article/830548/」の糸割りの節。**推測で決めた点**(父の確認待ち。数値は params で変えられるようにする):カウンターの目盛りは「1周 1,000m、中央の窓で周の数、10周(10,000m)まで」。番手は毛番手(メートル番手)で、長さ(m)= 正味の重さ(g)× 番手の数(単糸 1/48 なら 48、双糸 2/48 なら 24)。

**考え方**:糸は重さで管理されているので、コーンごとに残っている長さが違う。糸割り機は、口ごとに別のコーンから、同時にボビンへ巻き取る(最大12口)。足りないコーンのまま巻くと途中で糸が無くなるので、先に量って見極める。遊びの手応えは「数える・量って見極める・長さをぴたりと合わせる」の3つ。

**画面**(横長。論理座標 1000×750。縦長は盤面を上、操作欄を下)

- 盤面の左:糸の段ボール箱(品番・色の記号・色名。クリール立てと同じ絵)。箱の中は、残りの量が違うコーンが並ぶ。
- 盤面の中央:糸割り機。口を横一列に12並べる(縦長の画面でも1列。口の幅は盤面の幅÷12)。各口は、下に元のコーン、上に巻き取るボビン、そのあいだを糸が通る。口の下に番号 1〜12。使わない口は薄く描く。
- 盤面の右上:長さのカウンター(丸い目盛り盤)。目盛りは1周 1,000m、太い目盛り 100m ごと、細い目盛り 10m ごと。中央の窓に周の数(0〜9)。自動で止める長さに赤い針。盤の下に、今の長さを数字でも出す(例「3,250 m」。色と形だけに頼らない)。
- 盤面の右下:はかり(上皿の目盛りのはかり)。載せたコーンの重さを針と数字(例「182 g」)で示す。
- 操作欄:依頼書(品番・色・番手・1本あたりの長さ・本数)、今の段階の説明、段階ごとのボタン(下の「流れ」)。

**状態**:`phase: 'placing' | 'weighing' | 'setting' | 'winding' | 'empty' | 'tying' | 'done'`、お題(品番・番手・長さ・本数・紙管の重さ)、口ごとのコーン(残りの長さ・重さ、量ったかどうか)と巻いた長さ、箱の中のコーン、カウンター(自動か手動・止める長さ・今の長さ)、速さ(高速・低速・停止)、数え間違いの回数、見極めの記録、乱数の種。

**流れ**

1. **置く(placing)**:箱を選び、口を押すとコーンを置く。置いたコーンを押すと箱へ戻す。「量る」へ進むとき、置いた数が依頼の本数と違えば「依頼は 6 本です。口の数を確かめてください」と出し、数え間違いとして数える(進まない)。
2. **量る(weighing)**:置いたコーンを押すと、はかりに載って重さが出る。
   - 初級:重さの横に「約 4,300 m 巻けます」と、巻ける長さを画面が出す。
   - 中級:式を出す(「(182 g − 紙管 20 g)× 24 = ? m」)。答えは自分で考える。
   - 上級:重さだけ。紙管の重さと番手は依頼書から自分で読む。
   - 量ったコーンは「使う」「取り替える」を選ぶ。「取り替える」は箱の新しいコーン(満量。必ず足りる)に替える。量らずに進んでもよい。
3. **合わせる(setting)**:カウンターの「自動で止める」「手で止める」を選ぶ。自動では「+1周・−1周・+100m・−100m・+10m・−10m」で止める長さを合わせる。手では合わせない。「巻き始める」で winding。
4. **巻く(winding)**:すべての口が同時に巻く。速さは「高速」「低速」「停止」(ボタン、64px 以上)。
   - 自動:止める長さで機械が止まる(止める長さを間違えていれば、そのまま長さの誤差になる)。
   - 手:目盛りを見て「停止」を押す。手前で「低速」に落とすと合わせやすい。止めたあと、足りなければもう一度巻ける。巻きすぎは戻せない。
   - 「巻き終える」で done。
5. **糸が無くなる(empty → tying)**:足りないコーンの口は、残りの長さを巻いた時点で糸が無くなり、機械が止まる(ランプ、止まる音)。「5 番の口のコーンが空になりました。新しいコーンに替えて、糸を継いでください」。空のコーンを押すと新しいコーンに替わり、糸継ぎ(`core/mechanics/breakage.ts` の2手。コーン側の端とボビン側の端)をすると再開できる。
6. **終わり(done)**:ボビンを並べて見せ、成績を出す。

**難易度**(お題は乱数の種から作る。数値は `params.ts`)

| params | 初級 | 中級 | 上級 |
|---|---|---|---|
| 本数 | 4 | 6〜8 | 10〜12(帯の並び「1リピート 紺 3 本 × 4 くりかえし」から自分で数える) |
| 1本あたりの長さ | 2,000m | 3,000〜5,000m(100m 単位) | 3,000〜8,000m(10m 単位) |
| 番手 | 1/48 | 1/48・2/48 | 1/48・2/48・1/36・2/36 |
| 紙管の重さ | 0(はかりが正味を出す) | 20g(依頼書に書く) | 20〜30g(依頼書に書く) |
| 足りないコーン | 1 | 2 | 2〜3(足りるかどうかの境目の近いものを含む) |
| 巻く速さ(高速・低速) | 200・20 m/秒 | 250・20 | 300・20 |

**採点**

- 数え間違い:「量る」へ進めなかった回数。
- 見極めの誤り:足りないコーンを使ったまま巻き始めた数 + 足りるコーンを取り替えた数。
- 長さの誤差:ボビンの長さと依頼の長さの差(全口の最大)。
- 星3:数え間違い 0、見極めの誤り 0、誤差 `LENGTH_TOL_GOOD`(30m)以内。星2:数え間違いと見極めの誤りの合計が 2 以下、かつ誤差 `LENGTH_TOL_OK`(100m)以内。星1:それ以外。
- 成績欄:「本数の数え間違い 0回」「見極めの誤り 1(足りないまま使った 1・取り替えすぎ 0)」「長さ 3,020 m(依頼 3,000 m)」「糸継ぎ 1回」。
- 成績は records(id = `itowari`)。難易度ごとの星は `best['level:<1|2|3>']`(ドラム巻きと同じ形)。

**結果として残すもの**(FR-G6-06):品番・1本あたりの長さ・本数。仕事モードで、クリール立ての依頼書につなぐ。

**共有の仕組みの使い方**:糸継ぎは `breakage.ts` の `tapEnd` を使う(切れた糸 = 空になった口。`side` の 'creel' をコーン側、'drum' をボビン側と読み替える)。ペダル(`pedal.ts`)は使わない(糸割り機は速さの切り替えで動かす)。

### 6.2b ドラム設定(G7、P2c。案:管理者の確認待ち)

> 出どころ:お父さんへの確認(2026-10-03、管理者経由、会話)「ドラム巻きでいちばん大変だったのは、羽の角度と、1回転でどれだけずらすかの計算」。管理者「なるべくサプライズで見せたいので、計算式は確認役が調べて」。計算の考え方は、この節の前の「ドラム設定の計算」の記録。数値はすべて `params.ts` と内容のデータに置き、遊んで調整する。

**考え方**:ドラムに巻く前に、帯が羽の斜面に沿ってきれいに登っていくよう、機械に「羽の角度」と「1回転の送り量」を設定する。設定が合っていれば帯の端がきれいな斜面になり、少なすぎると同じ所に重なって潰れ、多すぎるとすき間ができて崩れる。手応えの中心は**計算して合わせること**(電卓を使ってよい)。

**計算(ゲームの中の決まり)**

1. 帯の密度 n(本/cm)= 帯の本数 ÷ 帯の幅(cm)
2. 1回転で太る厚み h(mm)= n × 糸の厚みの係数 c(番手ごと。下の表)
3. 1回転の送り量 s(mm)= h ÷ tan α(α:羽の角度)

| 番手(呼び方) | 糸の厚みの係数 c(mm・cm/本) | 使ってよい羽の角度 |
|---|---|---|
| 2/48(よんぱち) | 0.0085 | 7°・9°・11° |
| 2/60(ろくまる) | 0.0072 | 5°・7°・9°(細く滑りやすいので、急な角度は崩れる) |
| 1/20(紡毛) | 0.0110 | 9°・11°(太くふくらむので、ゆるい角度は送り量が大きくなりすぎる) |

- c は「1cm に1本並べたときに、1回転で増える厚み」。糸の太さ(番手が大きいほど細い)から決めた、ゲームの中の値。
- tan の値は表で見られる(5° 0.0875、7° 0.1228、9° 0.1584、11° 0.1944)。

**画面**(横長:盤面が左、操作欄が右。詰めた形は PU-09 と同じ考え)

- 盤面:ドラムの端の羽と、帯の断面を**横から大きく**見せる(ドラムの表面が下、羽の斜面が右へ登る)。設定を変えると、羽の角度の線が変わる。「試し巻き」で、帯の断面に糸の層が1回転ずつ積み上がる様子を見せる。
- 操作欄:依頼書(番手・帯の本数・帯の幅・巻く長さ)、計算のメモ(段階に応じて答えの一部を見せる。下の表)、**羽の角度**(選ぶ部品 `createChoice`。使えない角度は押すと理由)、**送り量**(大きな数字と「−0.1」「−0.01」「+0.01」「+0.1」のボタン。単位 mm)、「電卓」ボタン(重ね表示の簡単な電卓。四則と tan の表)、主な操作「試し巻き」。

**流れ**

1. 依頼書を読む。
2. 羽の角度を選び、送り量を計算して合わせる。
3. 「試し巻き」:約5秒で、帯の断面に 30 回転分の層が積み上がる。
   - 送り量が正しい値の ±5% 以内:層が羽の斜面にぴったり沿って登る(きれいな斜面)。
   - 少なすぎる(−5% を超える):層が同じ所に重なって盛り上がり、上が潰れて横に広がる(朱の印「潰れ」)。
   - 多すぎる(+5% を超える):層のあいだにすき間ができ、端が段になって崩れる(朱の印「崩れ」)。
   - 使えない角度(表にない角度)を選んだまま試すと、斜面で糸が滑って崩れる。
4. 結果:星と、正しい送り量(答え合わせ。計算の手順を表示)。何度でもやり直せる。

**段階ごとの手伝い**(お題は、クリール立て・ドラム巻きと同じ 15 題。柄と糸は同じ。帯の本数と幅は段階ごとに変える)

| 段階 | 計算のメモに見せるもの | 帯の本数・幅 |
|---|---|---|
| 1 | 密度・厚み h・角度ごとの tan | 400本・20cm |
| 2 | 厚み h・tan の表 | 480本・16cm |
| 3 | 密度だけ・係数の表・tan の表 | 540本・15cm |
| 4 | 係数の表・tan の表 | 600本・15cm |
| 5 | 何も見せない(手帳=表は電卓の重ね表示から見られる) | 720本・18cm |

**採点**:送り量の誤差(正しい値に対する割合)が 5% 以内で星3、15% 以内で星2、それ以外は星1。使えない角度を選んだら星1。成績欄:「羽の角度 9°」「送り量 2.15mm(正しい値 2.15mm)」「試し巻きの回数」。

**ドラム巻きとのつながり**:仕事の流れ(整経屋の一日)では、ドラム設定の出来をドラム巻きに引き継ぐ(誤差が大きいほど張りが乱れやすい)。単独で遊ぶときは引き継がない。

**置き場所**:ホームのカードで、クリール立てとドラム巻きのあいだ。名前「ドラム設定」(呼び名の変更の対象)。

### 6.3 ビーミング:改訂案(2026-10-04、確認役。管理者の了承済み。下の元の 6.3 より優先)

> 出どころ:お父さんへの確認(2026-10-03、管理者経由)「比較的難しくない。気を付けたのは、事前にビームの幅を合わせる(両端の円盤はバーベルのように動かせる)、張りを均一に巻く、ドラムの幅よりビームの幅が狭いので糸が偏らないようにする」と、お父さんが使っていた機械の写真(ビームは緑の円盤、白い糸が巻かれる)。

**手応えの中心は3つ**:①幅合わせ(準備)②均一な張り ③偏らせない。難しすぎないこと(お父さんの言葉どおり)。

**流れ**

1. **幅合わせ(準備)**:ビームを**正面から**大きく描く。左右の円盤(緑)を「◀」「▶」で動かして、依頼書の「巻き幅」(帯の幅 × 帯の数)に合わせる。巻き幅の目盛り(cm)を下に出す。誤差 ±1cm 以内で「合いました」。合わせ終えたら「巻き始める」。
2. **巻き返し**:ドラム(奥)から、全幅の糸のシートが降りてきてビームに巻かれる(正面の絵。巻いた厚みが少しずつ増える)。
   - **張り**:ドラム巻きと同じペダル(横向き)と張りのメーター。ただし流れはゆるやか、範囲は広め、引っかかりは無い(難しすぎないように)。
   - **偏り**:ドラムの幅のほうが広いので、糸のシートが左右にゆっくり寄っていく。「◀ 寄せる」「寄せる ▶」で、シートを円盤のあいだの中央に保つ。片方の円盤に寄りすぎると、その側の糸が円盤に乗り上げる(朱で示し、出来が下がる)。
   - **糸切れは起きない**(2026-10-04 管理者:「ビーム巻きで糸切れは発生しない。張りや偏りで品質が落ちるだけ」)。張りが範囲を外れたり、偏って円盤に乗り上げたりすると、出来(品質)が下がるだけ。
3. **完了**:満巻きのビームを大きく見せる。

**採点**:幅合わせの誤差、適正な張りで巻いた割合、中央に保てた割合(偏り)の3つ。どれも良ければ星3。成績欄にそれぞれを出す。時間の制限は無い。

**お題**:クリール立て・ドラム設定・ドラム巻きと同じ 15 の柄。巻き幅は、ドラム巻きの帯の数 × 帯の幅(ドラム設定の幅)。レベルが上がるほど、偏りの速さと張りの流れが少し強くなる。

**操作欄**(上から):メッセージ、依頼書(巻き幅・帯の数・柄)、幅合わせの段階では円盤を動かす4つのボタン(左の円盤 ◀▶・右の円盤 ◀▶。1行に4つ)、巻き返しの段階では張りのメーター・横向きのペダル・寄せるボタン(◀・▶)、一番下に主な操作。

### 6.3 ビーミング(G3、FR-G3)

> 資料メモ(2026-09-30、確認役):管理者が示した動画 `PiJPEGpx4Fo`(0:01)では、ドラム(奥の木の桟の円筒)から、全幅の糸のシートが何本もの銀色のローラーを通って、手前のビームへ巻き取られていく。ビームの両端のつばは**丸い穴がたくさん開いた金属の円盤**。P3 の絵はこれを手本にする。

**画面**:盤面の奥に巻き終えたドラム、手前に銀色のローラーと、両端に穴の開いたつばを持つビーム。全幅の糸のシートがドラムからローラーを経てビームへ流れる。操作欄はドラム巻きと同じ(ペダル、張りのメーター、巻き返した割合)。

**状態**:`phase: 'ready' | 'beaming' | 'broken' | 'tying' | 'done'`、巻き返した割合(0〜1)、ペダルと張り、糸切れ、適正範囲に入っていた時間の割合、元のドラムの帯ごとの出来、乱数の種。

3. 元のドラムで出来の悪かった帯の部分では、張りのぶれが少し大きくなる(前の工程の出来が次に響く)。
4. 巻き返し終えたら、満巻きのビームを大きく見せて done。

**長さ**:ペダルを半分ほど踏んだ速さで 40 秒程度。

**難易度**:ドラム巻きと同じ表の適正範囲・見せ方・切れやすさを使う。

**採点**:ドラム巻きと同じ基準。

**単独で遊ぶ場合**:元のドラムの出来はすべて 0.8 とみなす。

**仕事モード**:その仕事のドラム巻きの結果(帯ごとの出来)を引き継ぐ。

### 6.4 整経屋の一日(G4、FR-G4)

**画面**:作業場の俯瞰(灰緑の整経機が2台、のれんに屋号)。操作欄に日付、売上、評判、注文の一覧。

**状態**

```ts
interface ShopState {
  date: { year: number; month: number; day: number };  // 1967年4月1日から(創業の年)
  money: number;                 // 売上の累計(減らない)
  reputation: number;            // 評判 0〜100
  inbox: Order[];                // 受けていない注文
  machines: { id: MachineId; job?: ActiveJob }[];
  completed: CompletedJob[];     // 直近の実績(最大50件)
  seed: number;
}
interface Order { id: string; weaver: string; job: JobSpec; dueInDays: number; price: number; }
interface ActiveJob {
  order: Order;
  steps: ('creel' | 'winding' | 'beaming')[];   // 常にこの3工程
  stepIndex: number; daysUsed: number; stars: number[];
  sectionQuality?: number[];     // ドラム巻きの結果。ビーミングに渡す
}
```

**1日の流れ**

1. 朝:注文が 0〜2 件届く。件数と柄は評判と年代で決まる(`orderTemplates.json`)。
2. 割り当て:注文をタップしてから、空いている整経機をタップすると割り当てる。注文は断ることもできる(評判は下がらない)。
3. 仕事:割り当て中の整経機ごとに、今日の工程を「自分でやる」か「おまかせ」で進める。自分でやる場合は、その工程のゲームを GameModule の `mode: 'job'` で盤面に表示する。おまかせは星2で即完了する(ドラム巻きのおまかせでは帯ごとの出来をすべて 0.8 とする)。
4. 夕方:全部の整経機の今日の工程が終わったら「今日はおしまい」。1日の報告(進んだ工程、完成した仕事、売上、新しい柄)を表示して、翌日へ進む。1日ごとに自動保存する。

**工程**:すべての仕事が「クリール立て → ドラム巻き → ビーミング」の3工程。1工程が1日。1色の仕事はクリール立てが易しいお題になる。

**お金と評判**

- 仕事が完成すると、price × (星の平均 ÷ 3 × 0.5 + 0.5) を売上に加える。
- 評判は完成ごとに星の平均に応じて +1〜+3。納期を過ぎた場合は +0。評判を下げる仕組みは置かない。
- 費用や赤字の概念はない。倒産もない(01 5.3 の方針)。

**時間の進み方**:1日遊ぶごとに1か月進む。1967年(創業)から始まり、2004年まで進むと「長年のご愛顧ありがとうございました」の区切りの演出を出す。その後も2004年の年代のまま遊び続けられる。年代に応じて注文に出る柄が変わる。

**柄の登録**:完成した仕事の柄を図鑑に登録する。

### 6.5 柄の図鑑(G5、FR-G5)
